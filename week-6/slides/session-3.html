Part 2

Extract the Router

One giant server.ts is hard to navigate. Move todo routes into their own file.

Express.Router

// todo/routes/todo.routes.ts
import { Router } from "express";

export const todoRoutes = Router();

todoRoutes.get("/", listHandler);
todoRoutes.post("/", validate(createTodoSchema), createHandler);

Mount in app.ts

import { todoRoutes } from "./todo/routes/todo.routes.ts";

app.use(express.json());
app.use("/todos", todoRoutes);

todoRoutes.get("/") becomes GET /todos. The mount path is the prefix.

Part 3

Clean Architecture (Beginner)

Each layer has one job. Dependencies point inward — HTTP should not call Mongoose directly from routes.

Layer flow

Client
  → routes      (URL + middleware chain)
  → controller  (req/res, status codes)
  → service     (business rules + DB calls)
  → model       (Mongoose schema)
  → MongoDB

Zod schema validates at the boundary — usually on routes before the controller.

Router vs controller

  • Router — maps method + path + middleware to a handler
  • Controller — reads req, calls service, sends res with correct status
  • Service — owns Mongoose queries; no res.status here

Part 4

Domain-Driven Design (Beginner)

Group code by business area (todo/), not only by technical type (controllers/ mixed).

Bad: layer-only folders

src/
  controllers/   # all domains mixed
  models/
  routes/

Works for tiny apps. Gets messy when you add users, auth, notifications…

Better: todo/ domain

src/
  app.ts
  server.ts
  config/db.ts
  middleware/validate.ts
  todo/
    controller/todo.controller.ts
    routes/todo.routes.ts
    service/todo.service.ts
    model/todo.model.ts
    schema/todo.schema.ts

Request flow after refactor

Client → app.ts → todo.routes.ts → validate
  → todo.controller.ts → todo.service.ts → TodoModel

Part 5

Full CRUD

Complete the todo API with the right HTTP verbs and status codes.

CRUD mapping

  • CREATE — POST /todos → 201
  • READ (list) — GET /todos → 200
  • READ (one) — GET /todos/:id → 200 or 404
  • UPDATE (full) — PUT /todos/:id
  • UPDATE (partial) — PATCH /todos/:id
  • DELETE — DELETE /todos/:id → 204

PUT vs PATCH

PUT

  • Replace the entire resource
  • Send title and completed

PATCH

  • Update only what changed
  • Send { "completed": true } only

PATCH — mark complete

PATCH /todos/:id
{ "completed": true }

Use updateTodoSchema = createTodoSchema.partial() on PATCH routes.
