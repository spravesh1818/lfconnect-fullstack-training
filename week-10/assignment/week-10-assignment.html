Part 1 — Full PRD for a meeting-app feature

Write a PRD for the following feature:

"Users of the meeting app need to be able to send text messages within a meeting room. Messages should appear in real time for all participants currently in the room, and late joiners should be able to scroll back through recent message history. The chat must show the sender's display name and the time each message was sent."

PRD must include

SectionRequirement
Overview1 paragraph summary of the feature
Problem statementWho has this problem? What pain does chat solve?
Goals2–3 measurable outcomes (e.g., "participant can send a message in <2 s")
Non-goalsMinimum 2 explicit out-of-scopes (e.g., "no voice/video", "no file attachments v1")
User storiesMinimum 3 stories covering different roles (participant, host, late joiner)
Acceptance criteriaGiven/When/Then for at least 2 stories covering happy + sad paths
Open questionsMinimum 1 unanswered question that needs a product decision

Format

Write the PRD as a GitHub Issue titled PRD: In-room text chat in your meeting-app repo, or as a linked Notion/Google Doc. Use Markdown headings matching the sections above.

Part 2 — Sprint 2 Backlog

Break your PRD into a sprint backlog of 6–8 GitHub Issues for Sprint 2. These should cover the implementation of the in-room chat feature.

Issue requirements

FieldRequirement
TitleFormat: feat(scope): description — specific and actionable
BodyUser story + acceptance criteria (at least 2 Given/When/Then per issue)
Labelsfeat type label + size label (size:S, size:M, size:L)
MilestoneAssigned to "Sprint 2 - In-room chat" milestone
EstimateStory point value written in the issue body or as a label
BoardAll issues on the GitHub Project board in the Backlog column

Suggested issue breakdown

  • feat(messages): Message entity — store content, roomId, senderId, createdAt
  • feat(messages): MessagesModule — NestJS module, controller, service scaffold
  • feat(messages): POST /rooms/:id/messages — send a message (auth required)
  • feat(messages): GET /rooms/:id/messages — list message history (paginated)
  • feat(messages): WebSocket gateway — broadcast messages in real time
  • feat(messages): Message DTO — validate content (non-empty, max 1000 chars)
  • test(messages): Integration tests for message send and list endpoints

Part 3 — Implement one ticket with full Git workflow

Pick one issue from your Sprint 2 backlog and implement it using the full Git workflow practised in class.

Required workflow steps

StepRequirement
BranchFeature branch named according to convention: feat/messages-entity (example)
CommitsAt least 2 commits with conventional commit messages (feat(scope): description)
CIGitHub Actions workflow runs on the PR — must show a green checkmark
PR descriptionWhat changed, why, how to test, link to issue (Closes #N)
ReviewAt least one code review comment (from a partner or instructor) addressed
MergePR merged into main via squash-and-merge after CI passes and review is approved
CleanupFeature branch deleted after merge

Branch protection required

Your main branch must have branch protection enabled with:

  • PR required before merging
  • At least 1 approval required
  • CI status check required to pass

Full checklist

Part 1 — PRD

  • PRD has a title, overview, and problem statement
  • 2–3 measurable goals written
  • Minimum 2 non-goals explicitly listed
  • 3+ user stories in As a / I want / So that format
  • Given/When/Then acceptance criteria for at least 2 stories
  • At least 1 open question identified

Part 2 — Sprint Backlog

  • 6–8 GitHub Issues created in the meeting-app repo
  • Each issue has a user story and acceptance criteria
  • Each issue has a type label and a size label
  • "Sprint 2 - In-room chat" milestone created with a due date
  • All issues assigned to Sprint 2 milestone
  • All issues visible on the GitHub Project board (Backlog column)
  • Sprint goal written in the milestone description or as a pinned issue

Part 3 — Git Workflow

  • Feature branch created from main with correct naming convention
  • At least 2 conventional commits on the branch
  • GitHub Actions CI workflow exists (.github/workflows/ci.yml)
  • PR opened with a description and issue link (Closes #N)
  • CI shows green checkmark on the PR
  • At least 1 review comment addressed
  • PR merged via squash-and-merge after CI passes
  • Feature branch deleted after merge
  • Branch protection enabled on main
