Exercise 0 - Add a test script to meeting-app

GitHub Actions will run npm test. NestJS comes with Jest pre-configured. Verify it works locally first:

cd meeting-app
npm test

The default NestJS scaffold has a passing test in src/app.controller.spec.ts. If tests fail, fix them before moving on.

Confirm the script exists in package.json:

"scripts": {
  "test": "jest",
  "test:watch": "jest --watch",
  "test:cov": "jest --coverage"
}
Done when: npm test shows all tests passing locally.

Exercise 1 - Add a GitHub Actions CI workflow

Create the workflow file:

mkdir -p .github/workflows

Create .github/workflows/ci.yml:

name: CI

on:
  pull_request:
    branches: [main]
  push:
    branches: [main]

jobs:
  test:
    name: Run tests
    runs-on: ubuntu-latest

    steps:
      - name: Checkout code
        uses: actions/checkout@v4

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: npm

      - name: Install dependencies
        run: npm ci

      - name: Run tests
        run: npm test

Commit and push to main:

git add .github/workflows/ci.yml
git commit -m "chore: add GitHub Actions CI workflow"
git push
Done when: you can see the workflow running under Actions tab on GitHub and it shows a green checkmark.

Exercise 2 - Enable branch protection on main

  1. Go to your repo → Settings → Branches
  2. Click Add branch protection rule
  3. Branch name pattern: main
  4. Check these options:
    • [x] Require a pull request before merging
    • [x] Require approvals → 1 required
    • [x] Require status checks to pass before merging
    • Search for and select your CI status check: Run tests
    • [x] Require branches to be up to date before merging
    • [x] Do not allow bypassing the above settings
  5. Click Create
Done when: the branch protection rule shows on the Branches page and you can no longer push directly to main (you'll get a "protected branch" error).

Exercise 3 - Implement a story via the full PR workflow

Pick one of your Sprint 2 GitHub Issues. If you don't have one ready, use this one:

Issue: feat: POST /rooms/:id/messages — send a text message to a room

Create a feature branch:

git checkout main && git pull
git checkout -b feat/room-messages-post

Add a Message entity (src/messages/entities/message.entity.ts):

import {
  Entity, PrimaryGeneratedColumn, Column,
  ManyToOne, CreateDateColumn
} from "typeorm";
import { Room } from "../../rooms/entities/room.entity";
import { User } from "../../users/entities/user.entity";

@Entity()
export class Message {
  @PrimaryGeneratedColumn("uuid")
  id: string;

  @Column("text")
  content: string;

  @ManyToOne(() => Room, { onDelete: "CASCADE" })
  room: Room;

  @ManyToOne(() => User)
  sender: User;

  @CreateDateColumn()
  createdAt: Date;
}

Generate MessagesModule and wire everything up:

nest g resource messages --no-spec

Commit with conventional format:

git add .
git commit -m "feat(messages): add Message entity and MessagesModule"
Done when: the branch has at least one commit with a conventional message.

Exercise 4 - Open a PR and watch CI run

git push -u origin feat/room-messages-post

Open the PR on GitHub. Fill in the description template (use the one from Class 3 in Week 9). Link your issue with Closes #N.

Watch the Checks tab. Within ~2 minutes you should see the CI workflow run:

  • Green checkmark = tests pass, PR can be merged (pending review)
  • Red X = tests failed — check the logs and fix before requesting review
Done when: the PR has a green CI check and a filled-in description.

Exercise 5 - Simulate a merge conflict and resolve it

Have a partner make a small change to src/app.module.ts directly on their branch (or you do it in a second terminal) and merge it to main first. Then update your branch:

# On your feat/room-messages-post branch
git fetch origin
git merge origin/main

If there is a conflict, Git will mark it in the file:

<<<<<<< HEAD
  imports: [TypeOrmModule.forRoot(...), UsersModule, RoomsModule],
=======
  imports: [TypeOrmModule.forRoot(...), UsersModule],
>>>>>>> origin/main

Edit the file to keep both changes (your MessagesModule and their changes). Remove all conflict markers. Then:

git add src/app.module.ts
git commit   # git pre-fills the merge commit message
git push

The PR updates automatically. CI reruns.

Done when: the conflict is resolved, the branch is pushed, and CI is green again.

Troubleshooting

  • CI fails with "npm ci: missing package-lock.json" — commit package-lock.json to git. It should not be in .gitignore.
  • Status check not appearing in branch protection — the workflow must have run at least once (push to main or open a PR) before it appears in the status check list. Push a test commit first.
  • remote: error: GH006: Protected branch update failed — branch protection is working. Create a PR instead of pushing directly.
  • Merge conflict markers left in file — if you commit while markers (<<<<<<<) are still in the file, the app will fail to parse. Always check the whole conflict area before staging.
