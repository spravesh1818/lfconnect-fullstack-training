Week 10 - Class 2 Lab - Open session deck - Dockerize the meeting-app backend and deploy the full stack to a public URL

Goal

By the end of this lab your NestJS meeting-app backend runs on Render and your React frontend runs on Netlify — both on the public internet. You will be able to send a friend a URL and have them use your app.

Prerequisites: Docker Desktop installed and running, a GitHub account with your meeting-app repo pushed, and free accounts on render.com and netlify.com (both sign in with GitHub).

Done when: you can open your Netlify URL on your phone (off Wi-Fi) and log in successfully against the live Render backend.

Exercise 1 - Make the backend deploy-ready

Add a Dockerfile and .dockerignore to the root of meeting-app, and update main.ts to read the port from the environment.

  1. Create Dockerfile and .dockerignore from the templates below.
  2. Edit src/main.ts so the last line listens on the host's port and all interfaces:
// src/main.ts
app.enableCors();
await app.listen(process.env.PORT ?? 3000, '0.0.0.0');
Done when: both files exist at the repo root and main.ts uses process.env.PORT and '0.0.0.0'.
Dockerfile — copy to the root of meeting-app 
# ---- Stage 1: build ----

Exercise 2 - Build and run the container locally

Prove the image works before deploying. From the meeting-app folder:

docker build -t meeting-api .
docker run -p 3000:3000 --env-file .env meeting-api

Open http://localhost:3000 (or hit an endpoint like http://localhost:3000/auth/login with Postman). You should get the same responses as npm run start — but now from inside a container.

Done when: docker build finishes with no errors and the container responds on localhost:3000.

Exercise 3 - Deploy the backend to Render

  1. Commit and push the Dockerfile, .dockerignore, and main.ts changes to GitHub.
  2. On Render: New → Web Service → connect your meeting-app repo.
  3. Render auto-detects the Dockerfile and selects the Docker runtime. Choose the Free instance type.
  4. Under Environment, add your secrets — JWT_SECRET and any others your app reads. Do not add PORT; Render injects it.
  5. Click Create Web Service and watch the build log. When it says "Live", copy the https://<name>.onrender.com URL.
Done when: the Render dashboard shows "Live" and your onrender.com URL responds (allow ~40s for the first cold start).

Exercise 4 - Add a Postgres database

  1. On Render: New → PostgreSQL → Free plan → Create.
  2. Open the database and copy the Internal Database URL.
  3. Go to your web service → Environment → set DATABASE_URL to that Internal URL → Save. Render redeploys automatically.
  4. Check the logs to confirm the app connects to the database with no errors.
Done when: the backend redeploys cleanly and an endpoint that touches the DB (e.g. register/login) works against the live URL.

Exercise 5 - Deploy the frontend to Netlify

  1. On Netlify: Add new site → Import an existing project → pick your frontend repo.
  2. Build command: npm run build   Publish directory: dist (Vite) or build (Create-React-App).
  3. Under Environment variables, add VITE_API_URL = your Render backend URL.
  4. Add a file public/_redirects to your frontend repo with this one line, then push:
/*    /index.html   200

Make sure your frontend reads the API base from the env var, not a hard-coded localhost:

const API = import.meta.env.VITE_API_URL;
Done when: your your-site.netlify.app URL loads the app and refreshing on an inner route does not 404.

Exercise 6 - Connect them with CORS, end to end

  1. In meeting-app src/main.ts, allow your Netlify origin:
app.enableCors({
  origin: 'https://your-site.netlify.app',
  credentials: true,
});
  1. Commit and push — Render redeploys the backend.
  2. Open your Netlify site, register/log in, and perform a real action (create a room). Watch it hit the live backend in the Network tab.
Done when: you complete a full login + action from the deployed frontend with no CORS errors in the console.

Common deployment problems

  • App builds but Render shows "no open ports detected" — you hard-coded the port. Use process.env.PORT and bind to '0.0.0.0'.
  • "Blocked by CORS policy" in the browser, but Postman works — Postman ignores CORS. Enable CORS on the backend for your exact Netlify origin (no trailing slash), then redeploy.
  • Refresh on /dashboard gives 404 on Netlify — missing _redirects file in public/, or wrong publish directory.
  • First request after a break is very slow — free Render services spin down when idle; that's an expected cold start, not a bug.
  • Frontend still calls localhost in production — you didn't read VITE_API_URL, or you set it after the build (env vars must be present at build time, so trigger a redeploy).
Practice / stretch: Add a custom subdomain on Netlify, or set up a UptimeRobot ping every 10 minutes to keep your free Render backend warm. Share your live URL in the class channel and try each other's apps.
