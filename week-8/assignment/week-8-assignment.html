Assignment Part 1 — MinIO File Upload API

Migrate the in-class file-upload-api from Multer disk storage to MinIO object storage. Files are stored with a timestamp object key; the original filename is tracked in MongoDB.

Prerequisite — Session 1 class lab

Complete the in-class Class 1 hands-on first. Your repo must have working:

  • POST /files with Multer disk upload
  • GET /files listing metadata
  • GET /files/:id/download serving from disk
  • MongoDB fields: originalName, storedPath, mimeType, size

Part 1 requirements

Area Requirement
MinIO Docker MinIO on ports 9000/9001; bucket file-uploads (private)
Multer Switch to memoryStorage(); keep size limit and MIME filter
Upload PutObjectCommand with key ${Date.now()}-${req.file.originalname}
MongoDB Store originalName, objectKey, mimeType, size — remove storedPath
Download GET /files/:id/url returns presigned URL (60s TTL); remove or keep disk download route disabled
List GET /files still returns all file metadata

Part 1 — Step-by-step guide

Step 1 — Start MinIO

docker run -p 9000:9000 -p 9001:9001 \
  -e MINIO_ROOT_USER=minioadmin \
  -e MINIO_ROOT_PASSWORD=minioadmin \
  minio/minio server /data --console-address ":9001"

Open http://localhost:9001 — login minioadmin / minioadmin. Create bucket file-uploads.

Step 2 — Install SDK and env vars

npm install @aws-sdk/client-s3 @aws-sdk/s3-request-presigner
# .env (add to existing)
MINIO_ENDPOINT=http://localhost:9000
MINIO_ACCESS_KEY=minioadmin
MINIO_SECRET_KEY=minioadmin
MINIO_BUCKET=file-uploads

Mirror keys in .env.example with empty values.

Step 3 — S3 client factory

// src/config/minio.ts
import { S3Client } from "@aws-sdk/client-s3";

export const s3 = new S3Client({
  region: "us-east-1",
  endpoint: process.env.MINIO_ENDPOINT,
  forcePathStyle: true,
  credentials: {
    accessKeyId: process.env.MINIO_ACCESS_KEY!,
    secretAccessKey: process.env.MINIO_SECRET_KEY!,
  },
});

Step 4 — Update Multer to memoryStorage

export const fileUpload = multer({
  storage: multer.memoryStorage(),
  limits: { fileSize: 2 * 1024 * 1024 },
  fileFilter: (_req, file, cb) => {
    const allowed = ["image/png", "image/jpeg", "text/plain", "application/pdf"];
    cb(null, allowed.includes(file.mimetype));
  },
});

Step 5 — Upload handler with PutObject

import { PutObjectCommand } from "@aws-sdk/client-s3";
import { s3 } from "../config/minio.js";

const objectKey = `${Date.now()}-${req.file.originalname}`;

await s3.send(new PutObjectCommand({
  Bucket: process.env.MINIO_BUCKET!,
  Key: objectKey,
  Body: req.file.buffer,
  ContentType: req.file.mimetype,
}));

const doc = await FileModel.create({
  originalName: req.file.originalname,
  objectKey,
  mimeType: req.file.mimetype,
  size: req.file.size,
});

Step 6 — Update File model

const fileSchema = new Schema({
  originalName: { type: String, required: true },
  objectKey:    { type: String, required: true },
  mimeType:     { type: String, required: true },
  size:         { type: Number, required: true },
}, { timestamps: true });

Step 7 — Presigned download URL

import { GetObjectCommand } from "@aws-sdk/client-s3";
import { getSignedUrl } from "@aws-sdk/s3-request-presigner";

const url = await getSignedUrl(
  s3,
  new GetObjectCommand({
    Bucket: process.env.MINIO_BUCKET!,
    Key: doc.objectKey,
  }),
  { expiresIn: 60 }
);
res.json({ url, originalName: doc.originalName });

Step 8 — Test with curl

curl -X POST http://localhost:3000/files -F "file=@./notes.txt"
curl http://localhost:3000/files
curl http://localhost:3000/files/FILE_ID/url

Open the url from the last response in a browser — file content should match.

Part 1 checklist

  • MinIO container running; bucket file-uploads exists.
  • Upload stores object in MinIO with timestamp-prefixed key.
  • MongoDB has originalName matching the uploaded file's name.
  • MongoDB has objectKey — no storedPath on new uploads.
  • GET /files/:id/url returns a working presigned URL.
  • MinIO console shows the object with the timestamp key.
  • .env.example lists all MinIO vars (no real secrets).
  • README documents Docker MinIO command and curl test flow.

Part 1 submission

  • Repository link (file-upload-api)
  • Screenshot of MinIO console showing an uploaded object
  • Terminal log or recording: upload → list → presigned URL → download

Part 1 troubleshooting

  • AccessDenied — wrong access key/secret or bucket name mismatch.
  • ECONNREFUSED on port 9000 — MinIO container not running.
  • Bucket not found — create file-uploads in console.
  • req.file undefined — curl must use -F "file=@path".
  • Presigned URL 403 — verify object exists; credentials must match.
