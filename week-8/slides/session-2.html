Part 1

Two Apps, One Product

Your Todo API runs on :3000. Your React app runs on :5173. Different origins — the browser enforces CORS.

CORS on the API

import cors from "cors";

app.use(cors({
  origin: "http://localhost:5173",
}));

Without this, fetch from React fails with a CORS error in DevTools. Quick check: open http://localhost:3000/health from the browser after enabling CORS.

Frontend env

# todo-frontend/.env
VITE_API_URL=http://localhost:3000
const base = import.meta.env.VITE_API_URL;

Only VITE_* variables are exposed to client code. Never put secrets here — the bundle is public.

Request flow

  1. User logs in on React → API returns JWT
  2. React stores token in localStorage
  3. Every API call sends Authorization: Bearer …
  4. API requireAuth verifies before mutations

Part 3

Auth Layer

Reuse Week 4 patterns — provider at root, hook for consumers — but call your real API endpoints.

AuthContext shape

type AuthState = {
  token: string | null;
  user: { id: string; name: string; email: string } | null;
  login: (email: string, password: string) => Promise<void>;
  register: (name: string, email: string, password: string) => Promise<void>;
  logout: () => void;
};

On mount: read token and user from localStorage to survive refresh.

Login request

const res = await fetch(`${API_URL}/auth/login`, {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ email, password }),
});
if (!res.ok) throw new Error("Invalid credentials");
const { token, user } = await res.json();
localStorage.setItem("token", token);
localStorage.setItem("user", JSON.stringify(user));

API client with Bearer

export async function apiFetch(path: string, options: RequestInit = {}) {
  const token = localStorage.getItem("token");
  const headers = new Headers(options.headers);
  if (token) headers.set("Authorization", `Bearer ${token}`);
  const res = await fetch(`${API_URL}${path}`, { ...options, headers });
  if (res.status === 401) {
    localStorage.removeItem("token");
    window.location.href = "/login";
    throw new Error("Unauthorized");
  }
  return res;
}

ProtectedRoute

function ProtectedRoute({ children }: { children: React.ReactNode }) {
  const { token } = useAuth();
  if (!token) return <Navigate to="/login" replace />;
  return children;
}

Client guard improves UX. Server requireAuth is what actually blocks bad requests.

Part 4

Todo CRUD UI

Load todos

useEffect(() => {
  apiFetch("/todos")
    .then(r => r.json())
    .then(setTodos)
    .catch(setError)
    .finally(() => setLoading(false));
}, []);

Show loading spinner, error message, or empty state — three states users always hit.

Create todo

await apiFetch("/todos", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ title, completed: false }),
});

Clear the input and refetch — or optimistically append to local state.

Edit, delete, toggle complete

  • Edit title — PATCH /todos/:id with { title }
  • Delete — DELETE /todos/:id, remove from list
  • Toggle — checkbox calls PATCH with { completed: !todo.completed }

Routes sketch

<Route path="/login" element={<LoginPage />} />
<Route path="/register" element={<RegisterPage />} />
<Route path="/todos" element={
  <ProtectedRoute><TodosPage /></ProtectedRoute>
} />

Redirect / to /todos when logged in, else /login.

Part 5

FormData preview (Part 2 assignment)

Session 1 was a standalone file-upload-api. In Part 2 you upload event banners from React using the same multipart pattern.

Upload from React

const form = new FormData();
form.append("file", bannerFile);
await apiFetch(`/events/${eventId}/banner`, {
  method: "POST",
  body: form, // no Content-Type — browser sets multipart boundary
});

Do not set Content-Type: application/json on FormData requests.

Demo checklist

  • Register a new user
  • Login — land on todos page
  • Add two todos, toggle one complete
  • Edit a title, delete one todo
  • Logout — /todos redirects to login
  • POST without token via curl still returns 401
