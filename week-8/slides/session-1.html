Part 1

The Upload Problem

REST APIs usually speak JSON. A photo, PDF, or zip file is binary — you cannot embed it in {"name":"report"}.

multipart/form-data

  • HTTP content type built for HTML forms with files
  • One request carries text fields and a binary file part
  • Parts are separated by a boundary string
  • Browser <input type="file"> and curl -F both use it

Express parses JSON and urlencoded bodies by default. It does not parse multipart — that is Multer's job.

What a multipart request looks like

POST /files HTTP/1.1
Content-Type: multipart/form-data; boundary=----FormBoundary

------FormBoundary
Content-Disposition: form-data; name="file"; filename="notes.txt"
Content-Type: text/plain

(file bytes here)
------FormBoundary--

The field name file must match what Multer expects in upload.single("file").

Part 2

Multer Deep Dive

Multer is Express middleware that reads the multipart stream and gives you a usable req.file object.

single vs array vs fields

  • upload.single("file") — exactly one file in field file
  • upload.array("photos", 5) — up to 5 files in field photos
  • upload.fields([{ name: "avatar", maxCount: 1 }, { name: "gallery", maxCount: 8 }]) — mixed

Today we use single("file") — one upload per request.

req.file properties (disk storage)

  • originalname — name from the client, e.g. vacation.jpg
  • mimetype — e.g. image/jpeg
  • size — bytes
  • filename — name Multer saved on disk
  • path — full path, e.g. uploads/abc123-notes.txt

Always save originalname in MongoDB — disk filenames can be hashed or random.

diskStorage vs memoryStorage

diskStorage (today)

  • Writes to uploads/
  • req.file.path available
  • Good for learning and local demos

memoryStorage (assignment)

  • File in req.file.buffer
  • Upload buffer to MinIO in handler
  • No files left on server disk

limits and fileFilter

const upload = multer({
  storage: diskStorage,
  limits: { fileSize: 2 * 1024 * 1024 }, // 2 MB
  fileFilter: (_req, file, cb) => {
    const allowed = ["image/png", "image/jpeg", "text/plain", "application/pdf"];
    cb(null, allowed.includes(file.mimetype));
  },
});

Multer errors

  • LIMIT_FILE_SIZE — file exceeds limits.fileSize
  • LIMIT_UNEXPECTED_FILE — wrong field name sent
  • req.file undefined — client used JSON instead of multipart
if (err instanceof multer.MulterError) {
  return res.status(400).json({ error: err.code });
}

Step 4 — diskStorage middleware

// src/middleware/upload.ts
import multer from "multer";
import path from "node:path";
import { randomUUID } from "node:crypto";

const storage = multer.diskStorage({
  destination: "uploads/",
  filename: (_req, file, cb) => {
    const safe = file.originalname.replace(/[^a-zA-Z0-9._-]/g, "_");
    cb(null, `${randomUUID()}-${safe}`);
  },
});

export const fileUpload = multer({
  storage,
  limits: { fileSize: 2 * 1024 * 1024 },
  fileFilter: (_req, file, cb) => {
    const allowed = ["image/png", "image/jpeg", "text/plain", "application/pdf"];
    cb(null, allowed.includes(file.mimetype));
  },
});

Step 5 — File model

// src/file/model/file.model.ts
import { Schema, model } from "mongoose";

const fileSchema = new Schema({
  originalName: { type: String, required: true },
  storedPath:   { type: String, required: true },
  mimeType:     { type: String, required: true },
  size:         { type: Number, required: true },
}, { timestamps: true });

export const FileModel = model("File", fileSchema);

originalName = what the user uploaded. storedPath = where Multer saved it.

Step 6 — POST /files

// src/file/routes/file.routes.ts
import { Router } from "express";
import { fileUpload } from "../../middleware/upload.js";
import { uploadFile, listFiles, downloadFile } from "../controller/file.controller.js";

const router = Router();
router.post("/", fileUpload.single("file"), uploadFile);
router.get("/", listFiles);
router.get("/:id/download", downloadFile);

Step 6 — upload handler

export async function uploadFile(req, res) {
  if (!req.file) {
    return res.status(400).json({ error: "No file uploaded" });
  }
  const doc = await FileModel.create({
    originalName: req.file.originalname,
    storedPath: req.file.path,
    mimeType: req.file.mimetype,
    size: req.file.size,
  });
  res.status(201).json(doc);
}

Try this now: server boots; route is registered.

Step 7 — GET /files and download

export async function listFiles(_req, res) {
  const files = await FileModel.find().sort({ createdAt: -1 }).lean();
  res.json(files);
}

export async function downloadFile(req, res) {
  const doc = await FileModel.findById(req.params.id);
  if (!doc) return res.status(404).json({ error: "Not found" });
  res.download(doc.storedPath, doc.originalName);
}

Part 4

Why Disk Is Not Enough

Local uploads/ works on one laptop. Production has different constraints.

Production problems with local disk

  • Two API servers — file saved on server A is missing on server B
  • Docker redeploy — container filesystem is wiped
  • Backups and CDN integration are painful

Object storage (S3, MinIO) is the standard fix. You build that in the assignment — not today.

Part 5

MinIO Assignment Preview

After class, migrate file-upload-api from disk to MinIO object storage.

S3 vocabulary (for the assignment)

  • Bucket — container, e.g. file-uploads
  • Object key — unique name in bucket, e.g. 1739123456789-notes.txt
  • Endpoint — storage API URL, e.g. http://localhost:9000

MinIO runs S3 API locally via Docker. Same SDK code works on real AWS S3 later.

Part 6

Security Checklist

Before you ship uploads

  • Size limit — Multer limits.fileSize
  • MIME allowlist — do not trust extension alone
  • Sanitize filename — strip path characters from originalname
  • .gitignore uploads/ — never commit user files
  • Auth on mutations — optional stretch for this project
