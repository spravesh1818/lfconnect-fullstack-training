Exercise 3 - Create the webhook route

Create src/webhooks/stripe.router.ts:

import { Router, raw } from "express";
import Stripe from "stripe";
import { stripe } from "../stripe/stripe";

export const stripeRouter = Router();

stripeRouter.post(
  "/webhooks/stripe",
  raw({ type: "application/json" }),   // MUST be raw, not json()
  async (req, res) => {
    const sig = req.headers["stripe-signature"];
    let event: Stripe.Event;

    try {
      event = stripe.webhooks.constructEvent(
        req.body,
        sig as string,
        process.env.STRIPE_WEBHOOK_SECRET!
      );
    } catch (err) {
      console.error("Webhook signature verification failed:", err);
      return res.status(400).send("Signature invalid");
    }

    console.log("Received Stripe event:", event.type);

    switch (event.type) {
      case "payment_intent.succeeded": {
        const pi = event.data.object as Stripe.PaymentIntent;
        console.log("Payment succeeded:", pi.id, "amount:", pi.amount);
        // TODO: update your DB here
        break;
      }
      default:
        console.log("Unhandled event type:", event.type);
    }

    res.json({ received: true });
  }
);

Register the router in src/app.ts before any express.json() middleware:

import { stripeRouter } from "./webhooks/stripe.router";

// Register webhook route FIRST (needs raw body)
app.use(stripeRouter);

// Then register JSON middleware for the rest
app.use(express.json());
Done when: the server starts and the /webhooks/stripe route exists (you can confirm with curl -X POST http://localhost:3000/webhooks/stripe — expect 400 "Signature invalid", which is correct).

Exercise 4 - Forward events with Stripe CLI

In a new terminal window, start the Stripe CLI forwarder:

stripe listen --forward-to localhost:3000/webhooks/stripe

The CLI will print a webhook signing secret (whsec_…). Copy it into .env:

STRIPE_WEBHOOK_SECRET=whsec_…

Restart your server, then trigger a test event:

stripe trigger payment_intent.succeeded
Done when: your server logs show Received Stripe event: payment_intent.succeeded and the CLI shows 200 OK.

Exercise 5 - Handle the event in your DB (stretch)

In the payment_intent.succeeded case, update a record in your database. For example, if you have an Event model with a paymentStatus field:

case "payment_intent.succeeded": {
  const pi = event.data.object as Stripe.PaymentIntent;
  const eventId = pi.metadata?.eventId;
  if (eventId) {
    await Event.findByIdAndUpdate(eventId, {
      paymentStatus: "paid"
    });
    console.log("Marked event", eventId, "as paid");
  }
  break;
}

Use pi.metadata to carry your own data. Set metadata when creating the PaymentIntent (not needed today — just log for now).

Done when: the handler logs the metadata and (optionally) updates a DB record.

Troubleshooting

  • No signatures found matching the expected signature for payload — you are using express.json() on the webhook route. The webhook route must use express.raw(). Check that the raw middleware is applied before express.json().
  • stripe: command not found — the CLI is not installed or not on your PATH. Follow the install instructions above.
  • CLI shows [400] — check your server logs. Usually a missing webhook secret or body parser issue.
  • Server restarts but CLI still says old whsec_ — the CLI signing secret is session-specific. If you stop and restart stripe listen, it gives a new secret. Update .env and restart the server.
