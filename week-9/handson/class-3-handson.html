Week 9 - Class 3 Lab - Open session deck - Feature branches, conventional commits, PR workflow on meeting-app

Exercise 0 - Push meeting-app to GitHub

If your meeting-app is not on GitHub yet:

  1. Go to github.com → New repository → name it meeting-app
  2. Push your local repo:
cd meeting-app
git init           # if not already a git repo
git add .
git commit -m "chore: initial NestJS scaffold"
git remote add origin https://github.com/YOUR_USERNAME/meeting-app.git
git branch -M main
git push -u origin main
Done when: github.com/YOUR_USERNAME/meeting-app shows your code.

Exercise 1 - Create a feature branch

You are going to add a GET /rooms/:id endpoint. First, create a branch:

git checkout -b feat/rooms-get-by-id

Add the endpoint to src/rooms/rooms.service.ts:

findOne(id: string) {
  return this.roomRepo.findOne({
    where: { id },
    relations: ["host"],
  });
}

And in src/rooms/rooms.controller.ts:

import { Get, Param } from "@nestjs/common";

@Get(":id")
findOne(@Param("id") id: string) {
  return this.roomsService.findOne(id);
}
Done when: GET http://localhost:3000/rooms/<some-uuid> returns a room or null.

Exercise 2 - Commit with conventional commit format

git add src/rooms/rooms.service.ts src/rooms/rooms.controller.ts
git commit -m "feat(rooms): add GET /rooms/:id endpoint"

Convention: type(scope): short description

  • feat — new feature
  • fix — bug fix
  • chore — tooling, deps, config
  • refactor — code change without behaviour change
  • docs — documentation only
  • test — adding or fixing tests
Done when: git log --oneline shows a commit with the correct conventional format.

Exercise 3 - Push the branch and open a PR

git push -u origin feat/rooms-get-by-id

Go to your GitHub repository. GitHub will show a banner: "Compare & pull request". Click it.

Fill in the PR description using this template:

## What changed
Added `GET /rooms/:id` endpoint that returns a single room by UUID,
including the host relation.

## Why
Needed by the frontend to display room details.

## How to test
1. Create a room via `POST /rooms`
2. Copy the returned id
3. `GET /rooms/{id}` should return the room with host populated

## Checklist
- [x] Server starts without errors
- [x] GET /rooms/:id returns room or null
- [ ] Tests added (stretch goal)
Done when: the PR is open on GitHub with a title and description filled in.

Exercise 4 - Review a partner's PR

Swap GitHub usernames with a partner. Go to their repository and review their PR.

  1. Click the Files changed tab
  2. Add at least one inline comment — either a question, a suggestion, or a note
  3. Click Review changes → select Comment → Submit review

Good review comments:

  • Ask a clarifying question: "What happens if the id is not a valid UUID?"
  • Suggest an improvement: "Consider returning 404 instead of null when not found."
  • Note something good: "Clean separation — service handles the DB call, controller just delegates."
Done when: you have left at least one comment on a partner's PR and they have left one on yours.

Exercise 5 - Respond to review and merge (stretch)

Read the comment on your PR. If you agree:

  1. Make the change on your branch (e.g., add a 404 response)
  2. Commit and push
  3. Resolve the comment thread on GitHub
  4. Merge the PR into main (squash and merge recommended)
  5. Delete the branch after merging
# After merging, clean up locally
git checkout main
git pull
git branch -d feat/rooms-get-by-id
Done when: the PR is merged, the branch is deleted, and your local main is up to date.

Troubleshooting

  • error: src refspec feat/rooms-get-by-id does not match any — you haven't committed anything on the branch yet. Make at least one commit first.
  • GitHub doesn't show "Compare & pull request" — push the branch first (git push -u origin feat/rooms-get-by-id), then refresh the repo page.
  • Can't review your own PR — GitHub restricts self-reviews on some accounts. Use a partner's PR or add a second GitHub account as a collaborator to test the flow.
Practice: Create a second feature branch (feat/rooms-delete), add a DELETE /rooms/:id endpoint, open a PR, and go through the full review cycle again.
