Part 2

Component Thinking

We break one big UI into small, focused pieces.

Component Plan

App
 |- SearchForm
 |- StatusMessage

App owns state and API logic. Child components focus on rendering and events.

Why This Split Helps Beginners

  • Each file has one responsibility
  • Easier debugging when UI breaks
  • Reuse components in future apps
  • Cleaner code review and collaboration

Part 3

Props: Passing Data and Actions

Props are inputs sent from parent to child components.

Props Basics

  • Read-only data from parent component
  • Can include values (text, objects, arrays)
  • Can include callback functions for child events
  • Child should never mutate props directly

Example: Value Props

<WeatherCard
  city={weather.name}
  temperature={weather.main.temp}
  description={weather.weather[0].description}
/>

Example: Callback Props

<SearchForm
  city={city}
  onCityChange={setCity}
  onSearch={handleSearch}
/>

onSearch is a function passed to child and called on button click/form submit.

Part 4

State: Making UI Dynamic

State stores values that change over time and trigger re-renders.

State Variables We Need

  • city for input field value
  • weather for API success data
  • loading for request progress
  • error for user-facing failure messages

Initialize State with useState

const [city, setCity] = useState("");
const [weather, setWeather] = useState(null);
const [loading, setLoading] = useState(false);
const [error, setError] = useState("");

Controlled Input Pattern

<input
  value={city}
  onChange={event => setCity(event.target.value)}
  placeholder="Enter city"
/>

The input value always comes from React state.

Part 5

API Integration in React

Now we connect form submit with async weather fetch and UI updates.

Step 1: Build Request URL

const API_KEY = "YOUR_KEY";
const BASE_URL = "https://api.openweathermap.org/data/2.5/weather";
const url = `${BASE_URL}?q=${city}&appid=${API_KEY}&units=metric`;

Step 2: Submit Handler

async function handleSearch(event) {
  event.preventDefault();
  if (!city.trim()) return;
  // fetch in next step
}

Step 3: Loading and Error Flow

setLoading(true);
setError("");
try {
  // request and parse
} catch (err) {
  setError("Could not fetch weather");
} finally {
  setLoading(false);
}

Step 4: Save API Data to State

const response = await fetch(url);
if (!response.ok) throw new Error("City not found");
const data = await response.json();
setWeather(data);

Render by State Conditions

{loading && <StatusMessage text="Loading..." />}
{error && <StatusMessage text={error} type="error" />}
{weather && <WeatherCard weather={weather} />}

Part 6

Styling in React Apps

Let us clearly understand where styles live and how to choose approach.

Option 1: External CSS (Best for Beginners)

// App.jsx
import "./App.css";
  • Simple mental model
  • Same CSS skills from Week 1
  • Fast to start for classroom projects

Example App.css

.app {
  max-width: 560px;
  margin: 40px auto;
  padding: 20px;
  border-radius: 12px;
  background: white;
}
.search-button {
  background: #0f172a;
  color: white;
}

Option 2: CSS Modules (Intro)

// WeatherCard.jsx
import styles from "./WeatherCard.module.css";

<section className={styles.card}>...</section>
  • Locally scoped class names
  • Reduces class collision risk
  • Useful as project grows

Option 3: Inline Styles (Use Carefully)

<button style={{ padding: "10px", borderRadius: "8px" }}>
  Search
</button>
  • Good for one-off dynamic styles
  • Not ideal for large reusable style systems

Styling Approach Comparison

External CSS

  • Best beginner default
  • Familiar workflow
  • Shared global classes

CSS Modules / Inline

  • Better isolation with modules
  • Dynamic values with inline styles
  • Choose based on scale and team style

Part 7

React vs Vanilla JS Recap

Same weather app, different architecture and maintenance patterns.

Comparison: Vanilla JS vs React

Vanilla JS

  • Manual DOM queries and updates
  • State spread across functions
  • Quick start for tiny apps

React

  • State-driven rendering model
  • Reusable component architecture
  • Easier scaling for larger apps

Common Beginner Mistakes

  • Updating state directly instead of using setter
  • Forgetting event.preventDefault() in form submit
  • Passing wrong prop names to child components
  • Not handling loading and error states separately

Mini Checklist Before You Finish

  • Input controlled by city state
  • Search triggers API request
  • Loading/error/success UI conditions present
  • Weather card receives data through props
  • Styles applied consistently in chosen method
