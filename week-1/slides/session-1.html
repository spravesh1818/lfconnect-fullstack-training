Part 2

Internet and Web Basics

Understand how requests travel across the web and how modern web apps serve users.

What is the Internet?

  • A global network of connected devices and servers
  • Data moves through agreed protocols like TCP/IP and HTTP
  • The web is one service built on top of the internet

Step-by-Step Request Flow

  1. User enters a URL in the browser
  2. DNS resolves domain name to an IP address
  3. Browser sends HTTP request to that server
  4. Server sends HTML/CSS/JS response back
  5. Browser renders and executes the page

How a Web Application Works

  • Browser renders UI using HTML, CSS, and JavaScript
  • JavaScript calls backend APIs using HTTP and receives JSON
  • API server validates, runs business logic, and talks to the database
  • If frontend and API are on different domains, CORS rules apply

Flowchart: Browser to API to Database

Origins and CORS

An origin is the combination of scheme, host, and port (for example https://app.example.com).

  • Different subdomains are different origins (for example https://app.example.com vs https://api.example.com).
  • Browsers apply the same-origin policy so JavaScript cannot read another origin’s response by default.
  • CORS lets an API explicitly allow cross-origin browser requests with HTTP headers (high level only in this class).

Where Data Lives

  • Browser cache: fast and local, but temporary; users or the browser can clear it; not your system of record.
  • CDN / edge cache: speeds delivery and caching worldwide; still not the authoritative store for app records.
  • Database (with backups): durable storage for long-term application data the business relies on.

HTTP Responses and Status Codes

Every HTTP response includes a status code so clients know what happened.

  • 200: OK — request succeeded.
  • 301 / 302: redirect — the resource lives elsewhere now (or temporarily).
  • 404: not found — nothing matches that URL on the server right now.
  • 500: server error — the server had a problem handling the request.
  • You may still receive HTML on a 404 (a friendly error page), but the status code is what programs and APIs rely on.

Part 3

HTML5, CSS3 and Responsive Design

Build semantic structure first, then style and layout it for multiple screen sizes.

HTML5: What and Why

HTML5 is the modern standard for structuring web content with semantic meaning, media support, and cleaner APIs.

<!DOCTYPE html>
<html lang="en">
  <head>...</head>
  <body>...</body>
</html>

HTML5 History

  • 1991-1999: Early HTML versions focused on simple documents
  • 2004: WHATWG started improving web standards for real app needs
  • 2014: W3C published HTML5 recommendation
  • Now: HTML is a living standard continuously improved by WHATWG

Essential HTML Tags (Core Structure)

  • html, head, body, title, meta
  • h1-h6, p, a, strong, em
  • ul, ol, li, img, figure, figcaption
  • form, label, input, button

Block vs Inline Elements

Block Elements

  • Start on a new line
  • Usually take full available width
  • Examples: div, p, section

Inline Elements

  • Stay in the text flow
  • Width follows content size
  • Examples: span, a, strong

HTML5 Semantic Elements

  • header, nav, main, section, article, aside, footer
  • Media and graphics: audio, video, canvas, svg
  • These improve accessibility and make page intent clearer

MDN Reference for HTML

Use MDN as your daily reference when learning tags and attributes.

  • HTML element reference
  • HTML attribute reference

What is CSS3?

  • CSS describes how HTML should look: layout, color, type, and motion
  • Modern CSS is modular: features ship as separate specs (Flexbox, Grid, Color, and more)
  • Keep structure in HTML, presentation in CSS, behavior in JavaScript

History of CSS

  • Early web: presentation crept into HTML; CSS was created to separate style from content
  • CSS1 (1996): basic selectors, colors, fonts, simple boxes
  • CSS2 / 2.1: clearer layout rules, positioning, media types, tables, and more
  • “CSS3” era: new capabilities grouped as modules (not one monolithic version)
  • Today: browsers implement evergreen modules; authors follow stable features plus MDN

Classic CSS Foundations

  • Cascade and inheritance: rules compete; some values flow from parent to children
  • Selectors and declarations: what you target, and property:value pairs you set
  • Box model: every element occupies a rectangle of content, padding, border, and margin
  • Typography and color: readable text and consistent palettes
  • Floats and positioning: older layout tools; still appear in legacy codebases

Applying CSS from an HTML File

  • External stylesheet (recommended): <link rel="stylesheet" href="styles.css"> in head — reusable, cacheable, one source of truth
  • Embedded: <style>...</style> in head — fine for small experiments or single-file demos
  • Inline: style="" on an element — quick one-offs; hard to maintain at scale
  • @import inside CSS exists, but extra link tags are usually faster and simpler

The CSS Box Model

From the inside out: content, then padding, border, and margin (transparent space outside the border).

  • box-sizing: border-box makes width/height include padding and border (mental model most teams use today)
  • Without it, width often refers only to the content box (old “content-box” default)
* { box-sizing: border-box; }

Major CSS Property Groups

  • Typography: font-family, font-size, font-weight, line-height
  • Color and backgrounds: color, background-color, background-image
  • Spacing: margin, padding, gap (with Flexbox and Grid)
  • Borders and shadows: border, border-radius, box-shadow
  • Transitions: smooth changes between states (animation is a deeper topic later)

Selectors and Specificity

  • Class selectors are reusable and preferred for components
  • ID selectors are unique and have higher specificity
  • Descendant selectors like section p target nested structure

Layout and Positioning Overview

  • Normal flow: block elements stack; inline elements sit in text order
  • display: common values include block, inline, inline-block, none, flex, grid
  • position: static (default), relative, absolute, fixed, sticky — use sparingly and understand containing blocks
  • Modern pages combine flow + Flexbox and Grid for most layouts

Flexbox vs Grid

Flexbox

  • Best for one-dimensional rows or columns
  • Great for navbars, menus, and card alignment

Grid

  • Best for two-dimensional page sections
  • Great for dashboards and full-page layouts

Responsive Design Essentials

  • Add the viewport meta tag so mobile browsers use logical CSS width: <meta name="viewport" content="width=device-width, initial-scale=1">
  • Use fluid widths and max-width wrappers instead of one fixed pixel width for every device
  • Use relative units such as rem, em, and % so spacing and type scale with settings and screen size
  • Use media queries (@media) to change layout or typography past chosen breakpoints
  • Combine Flexbox or Grid with those tools so components reflow cleanly on small screens
