Part 1

Flexbox and CSS Grid

Go from “what the properties mean” to common patterns, then responsive layouts you can maintain.

Bridge from session 1

  • Normal flow is still the default: blocks stack, inline text wraps
  • Flexbox shines for one-dimensional alignment: a row of nav links, a column of stacked cards
  • CSS Grid shines for two-dimensional layouts: columns and rows at once (dashboards, page shells)
  • Most real pages mix flow + flex + grid in different regions

Flexbox mental model

  • A flex container is an element with display: flex (or inline-flex)
  • Its direct children become flex items (not deeper descendants)
  • Layout is described along two directions: the main axis and cross axis
  • The main axis follows flex-direction (for example row vs column)

Flex container: direction and wrapping

  • flex-direction: row (default), row-reverse, column, column-reverse
  • flex-wrap: nowrap (default) keeps one line; wrap moves overflow to new lines
  • flex-flow is shorthand for flex-direction + flex-wrap
.toolbar { display: flex; flex-flow: row wrap; gap: 0.5rem; }

Flex container: distributing space

  • justify-content — how items sit along the main axis (start, end, center, space-between, …)
  • align-items — how items align on the cross axis per line (stretch, flex-start, center, …)
  • align-content — when there are multiple flex lines, how those lines pack on the cross axis
  • gap — consistent spacing between items (and between lines when wrapped)

Flex items: grow, shrink, basis

  • flex-grow — how much of free space on the main axis this item should take (default 0)
  • flex-shrink — whether the item may shrink when space is tight (default 1)
  • flex-basis — starting size before growing/shrinking (often auto or a length)
  • Shorthand flex: 1 commonly means “take equal flexible space” (equivalent to 1 1 0% in many resets)

Flex items: self-alignment and order

  • align-self overrides align-items for a single item
  • order changes visual order with integers (default 0)
  • Use order sparingly: it can disagree with tab order and confuse keyboard and screen reader users unless you also fix focus order

Common Flexbox patterns

  • Horizontal nav: flex row + gap + align-items: center
  • Vertically centered hero: min-height section + flex column + justify-content: center
  • Sticky footer: body { min-height: 100vh; display: flex; flex-direction: column; } and main { flex: 1; } so the footer sits at the bottom when content is short
body { min-height: 100vh; display: flex; flex-direction: column; }
main { flex: 1; }

CSS Grid mental model

  • A grid container defines rows and columns as tracks
  • Items are placed into cells at the intersection of a row and column
  • Unlike flex’s “content-sized” rows, grid can size the whole track system up front
  • Grid lines are numbered (and can be named) for placement with grid-column / grid-row

Defining the grid

  • grid-template-columns and grid-template-rows list track sizes
  • fr (“fraction”) splits remaining space after fixed tracks
  • repeat(12, 1fr) or repeat(auto-fit, minmax(240px, 1fr)) reduce repetition
  • minmax(200px, 1fr) keeps a sensible minimum while still growing
  • grid-template-areas gives readable “ASCII art” layouts tied to grid-area on children
.layout {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(260px, 1fr));
  gap: 1rem;
}

Alignment in Grid

  • Item inside its cell: justify-items / align-items (or place-items shorthand)
  • Whole grid inside the container when extra room exists: justify-content / align-content
  • Single item override: justify-self / align-self

Same vocabulary as Flexbox (start/end/center), but applied to grid tracks and cells.

Flexbox vs Grid (when to reach for which)

Flexbox

  • Toolbars, chip lists, form rows, “distribute these siblings in one direction”
  • Great when the number of items is unknown or content-driven

Grid

  • Page shells, card galleries with strict columns, marketing sections with overlapping layers
  • Great when you think in rows and columns together

Responsive layout recap

  • Flex wrap: flex-wrap: wrap + sensible basis widths lets nav and chips reflow
  • Responsive grid: repeat(auto-fit, minmax(...)) builds as many columns as fit
  • Media queries: change grid-template-columns, gaps, or font sizes at breakpoints
  • Combine with fluid widths and rem from session 1 so the page scales across devices

Part 2

JavaScript basics

Add behavior in the browser: react to input, update the page, and prepare for deeper programming topics.

What is JavaScript here?

  • HTML structures content; CSS presents it; JavaScript can change structure, style, and fetch data
  • In this course track, we start with JS that runs in the browser alongside your pages
  • Later you will also run JavaScript on servers (Node.js) — same language, different environment APIs

How scripts attach to a page

  • External (common): <script src="app.js"></script> — cached, testable, reusable
  • Inline at the bottom of body or with defer: quick demos; keep larger code in files
  • defer downloads early but runs after HTML parse (good for many apps); async runs when ready (order not guaranteed)

Developer tools and the console

  • Open DevTools in your browser (often F12 or Cmd+Opt+I) and use the Console tab
  • console.log(value) prints values while you learn and debug
  • Red error messages point to file and line — read them slowly; they are your fastest teacher

Variables: let and const

  • let declares a block-scoped variable you may reassign
  • const declares a block-scoped binding that cannot be reassigned (object properties can still change)
  • Prefer const by default, then use let when you need reassignment
  • var exists in older code (function scope, hoisting quirks) — avoid in new projects
const title = "Hello";
let count = 0;
count += 1;

Types and typeof

  • Common primitives: string, number, boolean, undefined, bigint, symbol
  • null represents an intentional empty value (historically typeof null === "object" — a JS quirk)
  • typeof x returns a string describing the primitive type in many cases
typeof "hi";   // "string"
typeof 42;     // "number"
typeof true;   // "boolean"

Operators and type conversion

  • Arithmetic: + - * / % ** — e.g. 2 ** 10 is 1024
  • + also concatenates strings; mixing types can surprise you: "5" + 1 → "51", but "5" - 1 → 4 (subtraction coerces toward number)
  • Comparisons: prefer === and !== (value and type). Loose == / != allow coercion — avoid until you fully understand the rules
  • Logical: && || !; && and || short-circuit (skip the right side when the result is already decided)
  • Explicit conversion (clear “casting”): Number("12"), parseInt("10", 10), parseFloat("3.14"), String(42), template literals for strings, Boolean(value) (next slide: truthy/falsy in if)
  • Unary +value coerces to number (common in minified code); prefer Number(value) for readability while learning

Default habit: strict equality and explicit conversions when types might mix.

Control flow: decisions

  • if / else if / else choose branches based on conditions
  • Comparisons: === and !== test value and type (prefer these)
  • Values can be “truthy” or “falsy” in boolean contexts (for example empty string is falsy) — use explicit comparisons when unsure
if (count > 5) {
  console.log("many");
} else {
  console.log("few");
}

Loops

  • for loops are explicit: initializer, condition, afterthought
  • while repeats while a condition stays true
  • Use clear exit conditions to avoid infinite loops while learning
for (let i = 0; i < 3; i += 1) {
  console.log(i);
}

let n = 0;
while (n < 3) {
  n += 1;
}

Functions

  • Declaration: function add(a, b) { return a + b; } — hoisted in its scope
  • Arrow: const add = (a, b) => a + b; — concise; this behaves differently (we will revisit with objects and classes)
  • Functions are values: pass them to addEventListener, array methods, and timers

Arrays and objects (light touch)

  • Array: ordered list — [1, 2, 3], length via .length, access with items[0]
  • Object: keyed bag of properties — { name: "Ada" }, read with dot or ["bracket"] keys
  • Later: methods like map/filter, destructuring, and JSON

DOM bridge: query and react

The browser exposes the page as the Document Object Model. Your HTML becomes a tree of nodes you can read and update.

  • document.querySelector(".card") returns the first match (or null)
  • element.textContent = "Updated"; changes visible text inside that element
  • button.addEventListener("click", () => { ... }); runs code when the user clicks
const btn = document.querySelector("#go");
btn.addEventListener("click", () => {
  document.querySelector("#status").textContent = "Clicked!";
});
