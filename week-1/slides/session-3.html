Part 1

JavaScript deepening

Move from syntax knowledge to writing small, testable UI behavior with functions and arrays.

Bridge from session 2

  • You already know variables, conditions, loops, and basic DOM updates
  • Now we focus on writing reusable logic with functions
  • Then we connect that logic to user actions and page rendering
  • Final goal this class: publish a simple static app publicly

Function fundamentals

  • Functions package behavior with a name, inputs (parameters), and output (return value)
  • Prefer small functions with one clear responsibility
  • Use return when you want to pass data back to the caller
  • Functions without explicit return give undefined
function addTax(price, rate) {
  return price + price * rate;
}

Function styles you will see

  • Declaration: function greet(name) { ... }
  • Expression: const greet = function(name) { ... };
  • Arrow: const greet = (name) => ...;
  • Pick one style per file for consistency; arrow + const is common in modern frontend code

Pure functions and side effects

  • Pure: same input gives same output, does not mutate outside state
  • Side effect: touching DOM, console, network, storage, timers, globals
  • Good pattern: compute with pure functions, then do one render side effect
const total = calculateTotal(items); // pure
renderTotal(total);                  // side effect

Scope and closures

  • Variables declared inside a function are local to that function
  • let/const are block-scoped; var is function-scoped legacy
  • A closure happens when an inner function keeps access to outer variables
  • Closures are useful for counters, factories, and event handlers
function makeCounter() {
  let count = 0;
  return () => ++count;
}

Array methods for practical work

  • forEach for side effects like rendering logs
  • map transforms each item to a new array
  • filter keeps items matching a condition
  • find returns the first matching item (or undefined)
const activeNames = users
  .filter(user => user.active)
  .map(user => user.name);

Mini app flow: input -> function -> render

  1. Read input value from a form control
  2. Pass value into one or more functions
  3. Get result back and update output text in DOM
  4. Repeat this flow on each click or submit event
button.addEventListener("click", () => {
  const value = Number(input.value);
  const result = calculate(value);
  output.textContent = String(result);
});

Common beginner mistakes to catch early

  • Forgetting return in a function expected to produce a value
  • Mutating original arrays when you intended to create a new array
  • Using querySelector with the wrong selector (null errors)
  • Running script before DOM exists (place script at end of body or use defer)

Part 2

Git, GitHub, and deployment

Track changes, collaborate, and publish your static app publicly with GitHub Pages.

Why version control?

  • Git stores project history as commits
  • You can safely experiment and roll back to known good states
  • Core words: repository, commit, branch, remote, origin
  • GitHub hosts your remote repository and adds collaboration features

Local Git workflow (minimum commands)

git init
git status
git add .
git commit -m "Add feature"
git log --oneline
  • Commit often with meaningful messages (what/why)
  • Use git status before and after every commit

Connect to GitHub and push

git remote add origin https://github.com/<username>/<repo>.git
git branch -M main
git push -u origin main
  • Create a new repository on GitHub first
  • After first push, future pushes are usually just git push
  • Keep a clear README.md with project purpose and run notes

GitHub Pages for static sites

  • GitHub Pages hosts static files: HTML, CSS, JavaScript, images
  • For this class: deploy from main branch root
  • Your app needs an index.html at repository root
  • URL format: https://username.github.io/repository-name/

Deployment checklist (root on main)

  1. Ensure root has index.html and linked assets
  2. Commit and push latest code to main
  3. GitHub repo -> Settings -> Pages -> Deploy from branch
  4. Select branch main and folder / (root), then Save
  5. Wait for publish message and open generated URL

Common deployment issues and fixes

  • 404 page: verify repository name in URL and wait 1-2 minutes for publish
  • Blank page: open browser DevTools console for JS errors
  • Missing styles/images: check relative paths and file name casing
  • Old content: hard refresh browser and confirm latest commit is on GitHub
