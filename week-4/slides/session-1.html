Part 1

Global State Architecture

Choose the smallest state scope that satisfies product behavior.

When Context API Fits

  • Theme, auth user, locale, feature flags
  • Moderate update frequency, broad read access
  • Built-in React solution with no external dependency

Context Caveats

  • Provider updates can rerender many consumers
  • Large monolithic context becomes hard to maintain
  • Split providers by domain for better control

Part 2

Zustand Workflow

External store with selective subscriptions and lightweight API.

Why Teams Pick Zustand

  • Minimal boilerplate compared with many state libraries
  • Selectors can reduce unnecessary rerenders
  • Works well for medium-to-large shared app state

Context vs Zustand

Context

  • Built into React
  • Great for stable global values
  • Needs careful provider splitting

Zustand

  • External store abstraction
  • Selector-based subscriptions
  • Good for complex shared update flows

Part 3

Styling and UI Libraries

Balance velocity, consistency, and accessibility.

Tailwind Utility Strategy

  • Fast composition with predictable utility classes
  • Works best with design tokens and agreed naming patterns
  • Avoid class bloat by extracting repeating patterns

Component Libraries this Week

  • Required: Chakra UI for reusable application components
  • Optional extension: Radix UI primitives for advanced accessibility patterns
  • Combine with Tailwind carefully to avoid style conflicts

Part 4

Production Workflow

A feature is complete when it can be deployed confidently.

Dockerization Basics

  • Use multi-stage build for small runtime images
  • Build static assets in one stage, serve in lightweight runtime
  • Keep environment values externalized

Netlify Deployment Checklist

  • Set build command and publish directory correctly
  • Configure environment variables in Netlify dashboard
  • Verify SPA route fallback and production API behavior

Session Summary

  • Context and Zustand solve different scales of shared state
  • Tailwind + Chakra can ship fast consistent UIs
  • Radix is an optional primitive layer for advanced patterns
  • Docker + Netlify closes the loop from dev to deployment
