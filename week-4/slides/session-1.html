Part 1

Context API — Mental Model

Context shares values across a subtree without prop drilling. Best for stable, broadly read data (theme, auth user, locale).

When Context API Fits

  • Theme mode, signed-in user profile, locale
  • Moderate update frequency, many consumers
  • No extra package — built into React

Step 1 — Create context

// src/context/ThemeContext.jsx
import { createContext, useMemo, useState } from "react";

export const ThemeContext = createContext({
  mode: "light",
  toggle: () => {},
});

createContext needs a default value used when no provider is above a consumer.

Step 2 — Build the provider

export function ThemeProvider({ children }) {
  const [mode, setMode] = useState("light");

  const value = useMemo(
    () => ({
      mode,
      toggle: () =>
        setMode(current => (current === "light" ? "dark" : "light")),
    }),
    [mode]
  );

  return (
    <ThemeContext.Provider value={value}>
      {children}
    </ThemeContext.Provider>
  );
}

Step 3 — Wrap the app

// src/main.jsx
import { ThemeProvider } from "./context/ThemeContext.jsx";

createRoot(document.getElementById("root")).render(
  <ThemeProvider>
    <App />
  </ThemeProvider>
);

Place providers near the root so all routes and layouts can consume shared state.

Step 4 — Custom hook + consumer

import { useContext } from "react";
import { ThemeContext } from "./ThemeContext.jsx";

export function useTheme() {
  const ctx = useContext(ThemeContext);
  if (!ctx) throw new Error("useTheme must be used inside ThemeProvider");
  return ctx;
}

// Header.jsx
const { mode, toggle } = useTheme();
<button onClick={toggle}>Mode: {mode}</button>

Step 5 — Split providers by domain

<ThemeProvider>
  <AuthProvider>
    <App />
  </AuthProvider>
</ThemeProvider>

Separate ThemeProvider and AuthProvider so auth updates do not rerender theme-only consumers.

Verify Context works

  • Click toggle — header and any other consumer update together
  • Refresh page — default mode returns (unless you persist to localStorage)
  • React DevTools shows your provider tree above App

Done when: at least two components read theme without props.

Context pitfalls

  • Missing provider → consumers get default value silently
  • One giant context with fast-changing data → many rerenders
  • Putting fetch logic in context without memoization → extra work each render

Part 2

Zustand — Install and Create Store

External store with a small API. Great when multiple features share update-heavy state.

Install Zustand

# from your Vite + React project root
npm install zustand

No provider required — import the store hook directly in components.

Create a store

// src/store/useMeetingStore.js
import { create } from "zustand";

export const useMeetingStore = create(set => ({
  upcomingCount: 3,
  increment: () => set(state => ({ upcomingCount: state.upcomingCount + 1 })),
  reset: () => set({ upcomingCount: 0 }),
}));

Read with a selector

import { useMeetingStore } from "../store/useMeetingStore.js";

// only rerenders when upcomingCount changes
const count = useMeetingStore(state => state.upcomingCount);
const increment = useMeetingStore(state => state.increment);

<p>Upcoming: {count}</p>
<button onClick={increment}>Add meeting</button>

Always select the slice you need — avoid useMeetingStore() with no selector.

Update state from actions

// inside store
setMeetings: meetings => set({ meetings }),
addMeeting: meeting =>
  set(state => ({ meetings: [...state.meetings, meeting] })),

// in component
const addMeeting = useMeetingStore(s => s.addMeeting);
addMeeting({ id: "m-4", title: "Sprint Review" });

Context vs Zustand

Context

  • Built into React
  • Provider tree required
  • Great for theme, auth, locale

Zustand

  • npm install zustand
  • Selector-based subscriptions
  • Great for shared app workflows

Verify Zustand works

  • Two unrelated components show the same count
  • Clicking action in one updates the other without prop drilling
  • Components that select unrelated slices do not rerender on every store change

Done when: you can explain one case for Context and one for Zustand in your app.

Zustand pitfall

// causes rerender on ANY store change
const store = useMeetingStore();

// better
const meetings = useMeetingStore(s => s.meetings);

Part 3

Styling Stack — Tailwind + Chakra

Install each tool, wire it once, then compose: Tailwind for layout, Chakra for UI primitives.

Tailwind — Install (Vite)

npm install tailwindcss @tailwindcss/vite
// vite.config.js
import tailwindcss from "@tailwindcss/vite";

export default defineConfig({
  plugins: [react(), tailwindcss()],
});

Tailwind — Enable in CSS

/* src/index.css */
@import "tailwindcss";
// src/main.jsx
import "./index.css";

Restart dev server after first Tailwind install if styles do not appear.

Tailwind — Usage on layout

<main className="flex min-h-screen gap-4 p-4 bg-slate-50">
  <aside className="w-64 shrink-0 rounded-lg bg-white p-4 shadow-sm">
    …sidebar…
  </aside>
  <section className="flex-1 rounded-lg bg-white p-6">
    …content…
  </section>
</main>

Chakra UI — Install

npm install @chakra-ui/react @emotion/react

Same packages introduced in Week 3 — now we wire the provider and use components in pages.

Chakra UI — Provider in main.jsx

import { ChakraProvider, defaultSystem } from "@chakra-ui/react";

createRoot(document.getElementById("root")).render(
  <ChakraProvider value={defaultSystem}>
    <ThemeProvider>
      <App />
    </ThemeProvider>
  </ChakraProvider>
);

Chakra UI — Use components

import { Button, Card, Heading, Stack } from "@chakra-ui/react";

export default function QuickActions() {
  return (
    <Stack gap={4}>
      <Heading size="md">Quick Actions</Heading>
      <Card.Root>
        <Card.Body>
          <Button colorPalette="blue">Start Now →</Button>
        </Card.Body>
      </Card.Root>
    </Stack>
  );
}

Combining Tailwind + Chakra safely

  • Tailwind: page grid, spacing, responsive layout wrappers
  • Chakra: buttons, cards, modals, form controls
  • Avoid styling the same element with conflicting rules
  • Extract repeated utility groups into small layout components

Radix UI — Optional extension

npm install @radix-ui/react-dialog

import * as Dialog from "@radix-ui/react-dialog";

<Dialog.Root>
  <Dialog.Trigger>Meeting details</Dialog.Trigger>
  <Dialog.Portal>
    <Dialog.Content>…</Dialog.Content>
  </Dialog.Portal>
</Dialog.Root>

Use when you need accessible primitives beyond Chakra — not required for Week 4 baseline.

Verify styling stack

  • Tailwind classes visibly change layout (flex, gap, padding)
  • Chakra Button / Card render with theme styles
  • No console errors about missing Chakra provider

Done when: dashboard shell uses Tailwind and at least one Chakra component on the page.

Part 4

Docker — Build and Run Locally

Package your production build so anyone can run the same artifact with one command.

Why Docker for frontend apps?

  • Same build runs on any machine (laptop, CI, server)
  • Multi-stage images keep runtime small (nginx only serves dist/)
  • Useful before handing off to ops or running in cloud VMs

Prerequisite: docker --version works (Docker Desktop installed).

Dockerfile — multi-stage build

# Dockerfile
FROM node:20-alpine AS build
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build

FROM nginx:alpine
COPY --from=build /app/dist /usr/share/nginx/html
COPY nginx.conf /etc/nginx/conf.d/default.conf
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]

nginx.conf — SPA fallback

server {
  listen 80;
  root /usr/share/nginx/html;
  index index.html;

  location / {
    try_files $uri /index.html;
  }
}

Required so React Router deep links work after refresh inside the container.

.dockerignore

node_modules
dist
.git
.env
npm-debug.log

Keeps build context small and prevents copying secrets into the image.

Build the image

docker build -t meeting-basum .

First build may take a few minutes. Subsequent builds are faster with layer cache.

Run the container

docker run --rm -p 8080:80 meeting-basum

Maps host port 8080 → container port 80 (nginx).

Verify Docker locally

  • Open http://localhost:8080
  • Home/dashboard loads with styles
  • Navigate to nested route, refresh — page still loads
  • Stop container with Ctrl+C

Done when: app runs from image without npm run dev.

Docker env note (VITE_*)

# values are baked in at build time
ARG VITE_API_KEY
ENV VITE_API_KEY=$VITE_API_KEY
RUN npm run build

For local Docker demos, you can build without secrets if the app uses mock data. Never copy real .env into git.

Part 5

Netlify — Deploy and Verify Live

Ship the static dist/ folder to a public URL students can open and share.

Step 1 — Local production build

npm run build
ls dist

Confirm dist/index.html and asset files exist before deploying.

Step 2 — Netlify site settings

  • Build command: npm run build
  • Publish directory: dist
  • Node version: match your local LTS if builds fail on CI

Step 3 — Environment variables

# .env.local (never commit real keys)
VITE_TMDB_API_KEY=your_key_here

# access in React
const key = import.meta.env.VITE_TMDB_API_KEY;

Add the same keys in Netlify: Site settings → Environment variables. Rebuild after changes.

Step 4 — SPA fallback for React Router

# public/_redirects
/*    /index.html   200

Netlify serves this rule so refreshing /meetings/123 does not return 404.

Step 5 — Deploy options

  • Git-connected: push to GitHub → Netlify auto-builds on each push
  • Manual demo: drag-and-drop dist/ folder in Netlify UI

Git-connected deploy is preferred for the assignment so steps are reproducible.

Step 6 — Verify live deployment

  1. Open the Netlify URL (e.g. https://your-app.netlify.app)
  2. Click through sidebar routes — no full page reload
  3. Copy a deep link, open in new tab, refresh — still works
  4. Check browser console for missing env or asset errors

Done when: you can share a working public URL in your submission.

Docker vs Netlify

Docker

  • Portable runtime you control
  • Runs anywhere Docker is installed
  • Great for local prod parity and CI

Netlify

  • Managed static hosting
  • Fastest path to public URL
  • Built-in CDN and deploy previews

Troubleshooting deploy issues

  • Blank page: publish directory is not dist
  • 404 on refresh: missing _redirects SPA fallback
  • API fails in prod: VITE_* not set in Netlify before build
  • Stale UI: trigger a new deploy after env changes
