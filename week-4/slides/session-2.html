Part 1A

Forms in React — The Classical Way

Before libraries: one state object, controlled inputs, manual validation on submit.

Controlled inputs mental model

  • React state is the source of truth
  • Input shows value={form.title}
  • onChange updates state on every keystroke

This is the foundation every form library builds on.

Form state shape

const [form, setForm] = useState({
  title: "",
  date: "",
  participants: "",
});
const [errors, setErrors] = useState({});

One object for values, one object for field errors — keeps related data together.

Generic handleChange

function handleChange(e) {
  const { name, value } = e.target;
  setForm(prev => ({ ...prev, [name]: value }));
}

<input
  name="title"
  value={form.title}
  onChange={handleChange}
/>

handleSubmit with preventDefault

function handleSubmit(e) {
  e.preventDefault();
  const nextErrors = validateMeetingForm(form);
  setErrors(nextErrors);
  if (Object.keys(nextErrors).length > 0) return;
  onCreateMeeting(form);
}

<form onSubmit={handleSubmit}>…</form>

Without preventDefault, the browser reloads the page.

Manual validation function

function validateMeetingForm(values) {
  const errs = {};
  if (!values.title.trim()) errs.title = "Title is required";
  else if (values.title.length < 3) errs.title = "Min 3 characters";
  if (!values.date) errs.date = "Date is required";
  if (!values.participants.trim()) errs.participants = "Add a participant";
  return errs;
}

Show errors from state

{errors.title && (
  <p role="alert" className="text-red-600 text-sm">
    {errors.title}
  </p>
)}

Validation runs on submit (or on blur if you add that logic yourself).

Classical form pitfalls

  • Forgetting e.preventDefault() on submit
  • Duplicated handlers as fields grow
  • Validation rules scattered across JSX and helpers

Verify: empty submit shows errors; valid submit logs a clean payload.

Part 1B

react-hook-form

You just built registration, validation, and submit by hand — RHF automates that workflow.

What RHF gives you

  • register wires inputs without manual value/onChange per field
  • handleSubmit runs validation before your handler
  • formState.errors maps field names to messages

Install react-hook-form

# from your Vite + React project root
npm install react-hook-form

No provider required — call useForm() inside your form component.

useForm basics

import { useForm } from "react-hook-form";

export default function ScheduleMeetingForm() {
  const {
    register,
    handleSubmit,
    formState: { errors, isSubmitting },
  } = useForm({
    defaultValues: { title: "", date: "", participants: "" },
  });

  const onSubmit = data => console.log("valid payload", data);

  return (
    <form onSubmit={handleSubmit(onSubmit)}>
      …
    </form>
  );
}

register fields

<label>Meeting title</label>
<input {...register("title", { required: "Title is required" })} />
{errors.title && <p>{errors.title.message}</p>}

<label>Date</label>
<input type="date" {...register("date", { required: true })} />

register connects inputs to form state and validation rules.

Inline validation rules (first pass)

register("title", {
  required: "Title is required",
  minLength: { value: 3, message: "Min 3 characters" },
});

register("participants", {
  validate: value =>
    value.split(",").filter(Boolean).length >= 1
      || "Add at least one participant",
});

Works well for small forms — next we move rules into a Zod schema.

defaultValues, watch, reset

useForm({
  defaultValues: { title: meeting?.title ?? "", date: "", participants: "" },
});

const titlePreview = watch("title");
reset(); // after successful submit

Verify react-hook-form (inline rules)

  • Submit empty form → validation messages appear
  • Submit valid form → handler runs once with clean object
  • Compare code size to your classical version from Part 1A

Part 1C

Schema Validation with Zod

Define shape + rules once; plug into RHF with zodResolver.

Why Zod?

  • Single schema describes allowed shape and constraints
  • Readable validation rules outside JSX
  • Same schema can be reused on the server later
  • z.infer gives TypeScript types (Session 3 preview)

Install Zod + resolver

npm install zod @hookform/resolvers

Define meetingSchema

import { z } from "zod";

export const meetingSchema = z.object({
  title: z.string().min(3, "Title must be at least 3 characters"),
  date: z.string().min(1, "Date is required"),
  participants: z.string().min(1, "Add at least one participant"),
});

export type MeetingInput = z.infer<typeof meetingSchema>;

Wire zodResolver into useForm

import { useForm } from "react-hook-form";
import { zodResolver } from "@hookform/resolvers/zod";

const form = useForm<MeetingInput>({
  resolver: zodResolver(meetingSchema),
  defaultValues: { title: "", date: "", participants: "" },
});

Simpler register calls

<input {...register("title")} />
<input type="date" {...register("date")} />
<input {...register("participants")} />

{errors.title && <p>{errors.title.message}</p>}

Rules live in meetingSchema, not on each register call.

Refactor task

  1. Remove inline required / validate from register
  2. Move all rules into meetingSchema
  3. Keep the same UI and error display

Verify: change one rule in the schema and the form behavior updates everywhere.

  • Final form uses RHF + Zod (recommended for assignment)

Part 2

TanStack Table

The modern package is @tanstack/react-table (formerly react-table v7). Docs: tanstack.com/table

Install TanStack Table

npm install @tanstack/react-table

Headless UI — you control markup and styles (Tailwind/Chakra friendly).

Define columns and data

const columns = [
  { accessorKey: "title", header: "Meeting" },
  { accessorKey: "host", header: "Host" },
  { accessorKey: "time", header: "Time" },
  {
    id: "actions",
    header: "Action",
    cell: ({ row }) => (
      <button onClick={() => joinMeeting(row.original.id)}>Join</button>
    ),
  },
];

const data = [
  { id: "m1", title: "Project Planning", host: "Risan", time: "Today 10:00" },
];

useReactTable + core row model

import {
  flexRender,
  getCoreRowModel,
  useReactTable,
} from "@tanstack/react-table";

const table = useReactTable({
  data,
  columns,
  getCoreRowModel: getCoreRowModel(),
});

Render table markup

<table>
  <thead>
    {table.getHeaderGroups().map(hg => (
      <tr key={hg.id}>
        {hg.headers.map(header => (
          <th key={header.id}>
            {flexRender(header.column.columnDef.header, header.getContext())}
          </th>
        ))}
      </tr>
    ))}
  </thead>
  <tbody>
    {table.getRowModel().rows.map(row => (
      <tr key={row.id}>
        {row.getVisibleCells().map(cell => (
          <td key={cell.id}>
            {flexRender(cell.column.columnDef.cell, cell.getContext())}
          </td>
        ))}
      </tr>
    ))}
  </tbody>
</table>

Enable sorting

import { getSortedRowModel } from "@tanstack/react-table";

const table = useReactTable({
  data,
  columns,
  getCoreRowModel: getCoreRowModel(),
  getSortedRowModel: getSortedRowModel(),
});

// header click
<th onClick={header.column.getToggleSortingHandler()}>
  {flexRender(...)} {header.column.getIsSorted() === "asc" ? "↑" : "↓"}
</th>

Optional pagination

import { getPaginationRowModel } from "@tanstack/react-table";

getPaginationRowModel: getPaginationRowModel(),
// table.previousPage(), table.nextPage(), table.getPageCount()

Use when lists grow beyond one screen of meetings.
