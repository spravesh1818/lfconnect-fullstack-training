Project overview

Build a fresh Event Management Backend API for organizers to create and publish events. Use all Week 7 concepts together in one cohesive project.

Tech stack

  • Node.js + Express + TypeScript
  • MongoDB + Mongoose
  • Zod validation middleware
  • DDD folder structure (same pattern as Week 6 todo/)
  • Redis (caching + BullMQ)
  • Multer (file uploads)

Requirements by area

Area Requirement
Auth POST /auth/register, POST /auth/login; bcrypt passwordHash; JWT in .env; requireAuth on organizer mutations
Events CRUD on /events with fields: title, description, date, venue, capacity, status (draft | published); Zod validation; DDD event/ module
Caching Redis cache-aside on GET /events for published events only; invalidate on create/update/delete/publish; log CACHE HIT/MISS
Task queue When an event moves to published, enqueue a BullMQ job (e.g. notify-subscribers or generate-attendee-report); simulate 5s+ work; write log file or JSON to exports/; API returns without waiting
File upload POST /events/:id/banner with Multer; store banner path on event document; protected route
Worker Separate npm run worker script; worker shares REDIS_URL and MongoDB with API

Checklist

  • Fresh event-mgmt-api repo (not the Todo API).
  • Register + login work; duplicate email returns 409.
  • Only authenticated organizers can create/edit/delete events.
  • Public GET /events returns published events; draft events hidden from public list.
  • Second GET /events shows CACHE HIT in server logs.
  • Publishing an event invalidates cache and enqueues a background job.
  • Worker logs job completion; output file or clear log message exists.
  • Banner upload saves file under uploads/ and path in MongoDB.
  • .env.example lists MONGODB_URI, JWT_SECRET, REDIS_URL (no real secrets).
  • README documents Redis Docker command and two-terminal setup.

Curl test script (include in README or submission log)

# Health
curl http://localhost:3000/health

# Register organizer
curl -X POST http://localhost:3000/auth/register \
  -H "Content-Type: application/json" \
  -d '{"name":"Organizer","email":"org@example.com","password":"demo123456"}'

# Login — save token
curl -X POST http://localhost:3000/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"org@example.com","password":"demo123456"}'

# Create draft event (authenticated)
curl -X POST http://localhost:3000/events \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -d '{"title":"Tech Meetup","description":"Monthly meetup","date":"2026-07-15T18:00:00.000Z","venue":"Hall A","capacity":100,"status":"draft"}'

# Upload banner (replace EVENT_ID)
curl -X POST http://localhost:3000/events/EVENT_ID/banner \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -F "file=@./banner.png"

# Publish event — triggers background job + cache invalidation
curl -X PATCH http://localhost:3000/events/EVENT_ID \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -d '{"status":"published"}'

# Public list (first = MISS, second = HIT)
curl http://localhost:3000/events
curl http://localhost:3000/events

# Unauthenticated create (should 401)
curl -X POST http://localhost:3000/events \
  -H "Content-Type: application/json" \
  -d '{"title":"Fail"}'
