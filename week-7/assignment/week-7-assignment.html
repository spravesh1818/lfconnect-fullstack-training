Core Assignment — Add backend authentication

Add register/login and JWT-protected mutation routes to your Week 6 Todo API.

Requirements

  • All Week 6 requirements still met (CRUD, Zod, todo/ domain folders).
  • New auth/ domain with controller, routes, service, model, and schema subfolders.
  • POST /auth/register and POST /auth/login with Zod validation.
  • Passwords hashed with bcrypt — store passwordHash only.
  • JWT signed on login; JWT_SECRET in .env.
  • requireAuth middleware on POST/PUT/PATCH/DELETE for todos.
  • Public: GET /todos and GET /todos/:id.
  • Never return passwordHash in JSON responses.

Checklist

  • Register + login work; duplicate email returns 409.
  • Passwords are hashed in the database.
  • POST /todos without token returns 401.
  • POST /todos with valid Bearer token returns 201.
  • GET /todos works without token.
  • JWT_SECRET in .env.example (no real secret).

Curl test script (include in README or submission log)

# Health
curl http://localhost:3000/health

# Register
curl -X POST http://localhost:3000/auth/register \
  -H "Content-Type: application/json" \
  -d '{"name":"Demo User","email":"demo@example.com","password":"demo123456"}'

# Login — save token
curl -X POST http://localhost:3000/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"demo@example.com","password":"demo123456"}'

# Create todo (authenticated)
curl -X POST http://localhost:3000/todos \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -d '{"title":"Week 7 Demo"}'

# List todos (public)
curl http://localhost:3000/todos

# Mark complete (authenticated)
curl -X PATCH http://localhost:3000/todos/TODO_ID \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -d '{"completed": true}'

# Unauthenticated create (should 401)
curl -X POST http://localhost:3000/todos \
  -H "Content-Type: application/json" \
  -d '{"title":"Fail"}'
