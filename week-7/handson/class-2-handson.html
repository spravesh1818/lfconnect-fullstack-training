Exercise 2 - Redis connection

Create src/config/redis.ts:

import Redis from "ioredis";

const url = process.env.REDIS_URL ?? "redis://localhost:6379";
export const redis = new Redis(url);

redis.on("connect", () => console.log("Redis connected"));
redis.on("error", (err) => console.error("Redis error:", err.message));

Import and connect in server.ts (after DB connect). If Redis is down, log the error — the API should still boot for this lab.

Done when: npm run dev logs Redis connected.

Exercise 3 - Cache service helpers

Create src/cache/cache.service.ts:

import { redis } from "../config/redis.ts";

const DEFAULT_TTL_SECONDS = 60;

export async function cacheGet<T>(key: string): Promise<T | null> {
  try {
    const raw = await redis.get(key);
    return raw ? (JSON.parse(raw) as T) : null;
  } catch {
    return null;
  }
}

export async function cacheSet(key: string, value: unknown, ttl = DEFAULT_TTL_SECONDS) {
  try {
    await redis.set(key, JSON.stringify(value), "EX", ttl);
  } catch {
    // cache is optional — swallow and continue
  }
}

export async function cacheDel(key: string) {
  try {
    await redis.del(key);
  } catch {
    // optional
  }
}
Done when: helpers compile and export without errors.

Exercise 4 - Cache-aside on GET /todos

In your todo service (or list handler), wrap the list read:

const LIST_KEY = "todos:list";

export async function listTodos() {
  const cached = await cacheGet<Todo[]>(LIST_KEY);
  if (cached) {
    console.log("CACHE HIT", LIST_KEY);
    return cached;
  }

  console.log("CACHE MISS", LIST_KEY);
  const todos = await TodoModel.find().sort({ createdAt: -1 });
  await cacheSet(LIST_KEY, todos);
  return todos;
}

Wire GET /todos to call listTodos().

Done when: first curl http://localhost:3000/todos logs CACHE MISS; second call logs CACHE HIT.

Exercise 5 - Invalidate on writes

After create, update, and delete operations, clear the list cache:

await cacheDel("todos:list");

Add this to your create, update, and delete service methods (or controllers after successful writes).

Done when: create a todo → next GET shows the new item (CACHE MISS after invalidation).

Troubleshooting

  • ECONNREFUSED 6379 — start Redis with Docker; check REDIS_URL.
  • Always CACHE MISS — confirm cacheSet runs on miss; check Redis with redis-cli KEYS '*'.
  • Stale list after create — you forgot cacheDel on write paths.
  • JSON.parse error — only cache JSON-serializable data; Mongoose docs need .lean() or map to plain objects.
