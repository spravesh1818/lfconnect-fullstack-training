Part 2

Scaling at Application Level

More users → more requests. Two broad strategies before you reach Kubernetes-level infra.

Vertical vs horizontal

Vertical

  • Bigger CPU/RAM on one server
  • Simple but has a ceiling

Horizontal

  • More API instances behind a load balancer
  • Needs shared Redis/DB; stateless APIs help

The long-running work problem

  • Send 10,000 emails after event publish
  • Generate PDF/CSV report from 50k rows
  • Resize uploaded images

Never hold an HTTP request open for 30+ seconds. Users timeout; one slow job blocks a server thread.

Part 3

Task Queues

Decouple “accept work” from “do work.” API enqueues; worker processes in the background.

Producer → Queue → Worker

  1. Producer — Express route adds a job to the queue
  2. Queue — Redis-backed BullMQ holds pending jobs
  3. Worker — separate Node process picks up jobs and runs handlers

API returns 202 Accepted with jobId in milliseconds.

Request flow

Client  →  POST /todos/export
API     →  queue.add("export-todos", { requestedBy })
API     →  202 { jobId: "abc123" }
Worker  →  fetch todos, simulate delay, write exports/todos.json
Worker  →  log "Export complete"

Part 4

BullMQ

Popular Redis-backed queue for Node.js. Same REDIS_URL as Session 2.

Queue (API side)

import { Queue } from "bullmq";

export const todoExportQueue = new Queue("todo-export", {
  connection: { url: process.env.REDIS_URL },
});

const job = await todoExportQueue.add("export-todos", {
  requestedBy: req.userId,
});
res.status(202).json({ jobId: job.id });

Worker (separate process)

import { Worker } from "bullmq";
import fs from "node:fs/promises";

new Worker("todo-export", async (job) => {
  if (job.name !== "export-todos") return;
  await new Promise((r) => setTimeout(r, 5000)); // simulate work
  const todos = await TodoModel.find().lean();
  await fs.writeFile("exports/todos.json", JSON.stringify(todos, null, 2));
  console.log("Export job", job.id, "complete");
}, { connection: { url: process.env.REDIS_URL } });

Run two terminals

# Terminal 1 — API
npm run dev

# Terminal 2 — worker
npm run worker

In package.json: "worker": "tsx src/workers/todo.worker.ts"

Part 5

Multer File Uploads

HTTP JSON cannot carry binary files. Use multipart/form-data and Multer middleware.

Disk storage setup

import multer from "multer";

const upload = multer({
  dest: "uploads/",
  limits: { fileSize: 2 * 1024 * 1024 }, // 2 MB
});

todoRoutes.post("/:id/attachment", requireAuth, upload.single("file"), attachHandler);

Client sends field name file. Handler reads req.file.path and saves path in MongoDB.

Upload with curl

curl -X POST http://localhost:3000/todos/TODO_ID/attachment \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -F "file=@./notes.txt"

Validate MIME type and size in production. Class uses local uploads/; production moves to S3.

Production notes

  • Idempotent jobs — safe to retry without duplicate side effects
  • Attempts + backoff — BullMQ retries failed jobs automatically
  • Dead-letter queue — inspect jobs that fail permanently
  • File storage — S3 + signed URLs instead of local disk in production
