Core Assignment A - Frontend state architecture (Context API + Global State)

Implement state architecture in your Meeting Basum app using both Context API and a global store pattern (for example Zustand style).

Requirements

  • Use Context API for user/session-level state (for example current user, theme, or workspace settings).
  • Use a global store for meetings data and shared actions (list/add/update/remove).
  • Keep local UI-only state out of global state (modals, temporary filters, single-input text).
  • Add a short README note comparing why each state location was chosen.

Checklist

  • Context provider exists and is used by at least 2 components.
  • Global store exists and is used by at least 3 components/routes.
  • At least one derived state value is computed (for example upcoming meetings count).
  • README includes a Context-vs-global-store decision note.

Core Assignment B - Docker + Netlify delivery

Package and ship your frontend app like a production team.

Requirements

  • Create a Dockerfile for the client app and ensure it runs locally.
  • Add a .dockerignore and document how to build and run the image.
  • Deploy the app to Netlify and share the live URL.
  • Document build command, publish directory, and SPA fallback setup in README.

Checklist

  • docker build succeeds and image runs without local source mounts.
  • App is reachable at the shared Netlify URL.
  • Refresh on a deep route does not 404 on Netlify.
  • README includes exact commands used for Docker build/run and deployment settings.

Core Assignment C - TypeScript basics + server concepts

Build a small TypeScript server that demonstrates request lifecycle fundamentals and REST basics.

Requirements

  • Use Express + TypeScript with strict: true.
  • Implement these endpoints: GET /health, GET /meetings, POST /meetings.
  • Return appropriate status codes (200, 201, 400, 404 where relevant).
  • Add middleware that logs method, route, status, and duration.
  • Use at least one TypeScript type and one interface meaningfully.
  • Add one short README section explaining the lifecycle of one request in your app.

Checklist

  • Server boots with a single command and responds on documented port.
  • Endpoints return valid JSON and expected status codes.
  • Logger middleware output is visible in terminal logs.
  • README contains the request lifecycle explanation.

Challenge 1 (Hard) - State architecture optimization

Push your state system beyond basic CRUD. This challenge is designed to be difficult.

Task

  • Split your state into clear boundaries (Context responsibilities vs store responsibilities).
  • Add derived selectors (for example today's meetings, meetings by host, overdue count).
  • Prevent unnecessary re-renders in at least one hot UI area (list/table/filter panel).
  • Add a short performance note with before/after evidence (React DevTools screenshot or explained measurement).

Checklist

  • Selectors are reusable and not duplicated in multiple components.
  • At least one optimization is clearly implemented and evidenced.
  • README includes optimization rationale and tradeoff discussion.

Challenge 2 (Hard) - Delivery hardening (Docker + Netlify parity)

Harden your deployment workflow to mimic real project delivery conditions.

Task

  • Create a multi-stage Docker build for the frontend app.
  • Ensure local Docker output behavior matches Netlify deployment behavior.
  • Introduce one environment variable and document safe handling across local and Netlify.
  • Add a failure-recovery note: what to check first if deployment succeeds but app fails at runtime.

Checklist

  • Multi-stage Dockerfile builds successfully.
  • Netlify deployment still works after Dockerization changes.
  • Environment variable usage is documented with no secrets committed.
  • README includes a concise deployment troubleshooting runbook.

Final consolidated grading checklist

  • Context API and global state are both implemented with clear responsibility split.
  • Frontend app is dockerized and reproducible with documented commands.
  • Netlify live URL is submitted and route refresh works.
  • TypeScript basics are applied in frontend and server code (no unchecked any usage).
  • Server concepts are demonstrated via endpoints, middleware, and status code handling.
  • Challenge 1 and Challenge 2 are each completed with evidence artifacts.
  • Submission includes repo link, Netlify URL, Docker output proof, and architecture notes.
