Part 1

React Router: Params, Queries, and Nesting

Session 2 covered BrowserRouter, Routes, Link, and catch-all routes. Here we model real apps: IDs in the path, filters in the query string, nested layouts, and a full app shell pattern.

Path parameters and useParams

<Route path="/posts/:postId" element={<PostDetail />} />

import { useParams } from "react-router";

export default function PostDetail() {
  const { postId } = useParams();
  return <p>Loading post {postId}</p>;
}

Colon segments capture URL parts. useParams() returns an object of those values (strings). Use them to load data or choose which child view to show.

Query parameters and useSearchParams

import { useSearchParams } from "react-router";

export default function Search() {
  const [searchParams, setSearchParams] = useSearchParams();
  const q = searchParams.get("q") ?? "";

  return (
    <>
      <input
        value={q}
        onChange={e => setSearchParams({ q: e.target.value })}
      />
    </>
  );
}

Query strings suit filters, tabs, pagination — shareable state in the URL without new path segments. useSearchParams is like local state synced to ?key=value.

Nested routes and Outlet

// parent layout wraps child routes
<Route path="/dashboard" element={<DashboardLayout />}>
  <Route index element={<DashboardHome />} />
  <Route path="settings" element={<Settings />} />
</Route>

// DashboardLayout.jsx
import { Outlet } from "react-router";

export default function DashboardLayout() {
  return (
    <div>
      <nav>…</nav>
      <Outlet />  {/* child route renders here */}
    </div>
  );
}

Child paths are often relative to the parent (settings → /dashboard/settings). <Outlet /> is the slot for the active child route.

App shell: one layout route for persistent chrome

  • An app shell is the UI that stays put while users navigate: header, primary nav, optional sidebar or footer.
  • Put that chrome in a layout route component; avoid copying the same header into every page.
  • Only the region around <Outlet /> swaps — typically your main content column.
  • You can use different shells for different areas (e.g. marketing layout vs authenticated app layout) by using different parent Route trees.

App shell route table pattern

<Route element={<AppShell />}>
  <Route path="/" element={<Home />} />
  <Route path="dashboard" element={<DashboardLayout />}>
    <Route index element={<DashboardHome />} />
    <Route path="reports" element={<Reports />} />
  </Route>
</Route>

// AppShell.jsx — site-wide chrome
import { Outlet } from "react-router";

export default function AppShell() {
  return (
    <div className="app">
      <header>…</header>
      <main>
        <Outlet />
      </main>
      <footer>…</footer>
    </div>
  );
}

Use an index child when the parent path should show a default page (e.g. /dashboard → DashboardHome). Nest another layout (DashboardLayout) when a section needs its own sub-nav around its Outlet.

Part 2

Memoization in Practice

Optimization is useful only when it solves a measured problem.

useMemo Purpose

  • Cache expensive computed values between renders
  • Recompute only when dependencies change
  • Not required for trivial operations

useCallback Purpose

  • Stabilize function identity across renders
  • Useful when passing callbacks to memoized children
  • Can add noise if used everywhere without reason

When Memoization Backfires

  • Dependency arrays are wrong or too broad
  • Code becomes harder to reason about
  • Cost of memoization exceeds saved work

Part 3

Custom Hooks

Encapsulate reusable stateful logic while keeping components focused on UI.

What Makes a Good Custom Hook

  • Single responsibility and predictable API
  • Clear input/output contract
  • No hidden side effects beyond what name implies

Custom Hook Example: definition

function useDebouncedValue(value, delayMs) {
  const [debounced, setDebounced] = useState(value);
  useEffect(() => {
    const id = setTimeout(() => setDebounced(value), delayMs);
    return () => clearTimeout(id);
  }, [value, delayMs]);
  return debounced;
}

Using useDebouncedValue in a component

import { useState, useEffect } from "react";
// import useDebouncedValue from "./hooks/useDebouncedValue";

export default function SearchBox() {
  const [query, setQuery] = useState("");
  const debouncedQuery = useDebouncedValue(query, 400);

  useEffect(() => {
    if (!debouncedQuery.trim()) return;
    fetchSuggestions(debouncedQuery);
  }, [debouncedQuery]);

  return (
    <input
      value={query}
      onChange={e => setQuery(e.target.value)}
      placeholder="Search…"
    />
  );
}

The hook returns the delayed copy of value. Keep fast UI state in query; run expensive work (API calls, heavy filters) off debouncedQuery after typing pauses.

Dependency Pitfalls in Hooks

  • Missing dependencies cause stale data
  • Unstable references trigger unnecessary reruns
  • Move stable utilities outside component when possible

Part 4

Higher-Order Functions + Best Practices

Readable transforms and bounded component responsibilities reduce long-term bugs.

HOFs in React Code

  • map for list rendering
  • filter for scoped subsets
  • reduce for aggregate state
  • Prefer pure transforms over inline mutation

Best Practices Checklist

  • State minimalism over state duplication
  • Effects only for side effects, not pure derivations
  • Memoization only where profiling suggests value
  • Hooks and utility abstractions named by intent
