Part 1

Client-Side Routing with React Router

URLs should reflect what the user sees: shareable links, back/forward, and navigation without full page reloads. We expand on the Session 1 react-router install teaser.

Install and app shell

# install
npm install react-router

Wrap the tree that needs routing once with <BrowserRouter> — typically in main.jsx around <App /> or at the top of App.jsx. Without it, Link and route hooks have no router context.

Older material may still show react-router-dom; it largely re-exports react-router. Prefer react-router for new apps.

Routes and Route (v6)

import { Routes, Route } from "react-router";
import Home from "./pages/Home.jsx";
import About from "./pages/About.jsx";

export default function AppRoutes() {
  return (
    <Routes>
      <Route path="/" element={<Home />} />
      <Route path="/about" element={<About />} />
    </Routes>
  );
}

Declare the route table in one place. Each path maps to an element (a React node).

Link and NavLink

import { Link, NavLink } from "react-router";

<Link to="/about">About</Link>

<NavLink
  to="/about"
  className={({ isActive }) => (isActive ? "nav-link active" : "nav-link")}
>
  About
</NavLink>

Use Link / NavLink for in-app paths so React Router updates the URL without a full document reload. Reserve plain <a href> for external sites or downloads.

404 route and programmatic navigation

<Route path="*" element={<NotFound />} />

// optional: redirect or navigate after an action
import { useNavigate } from "react-router";

const navigate = useNavigate();
navigate("/thanks");

path="*" matches when nothing else does — your “not found” page. useNavigate() is useful after login, form submit, or guard logic.

Session Summary

  • Prefer Link / NavLink for in-app navigation; use path="*" and useNavigate for not-found and redirects
