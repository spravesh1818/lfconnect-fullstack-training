Part 1

Memoization in Practice

Optimization is useful only when it solves a measured problem.

useMemo Purpose

  • Cache expensive computed values between renders
  • Recompute only when dependencies change
  • Not required for trivial operations

useCallback Purpose

  • Stabilize function identity across renders
  • Useful when passing callbacks to memoized children
  • Can add noise if used everywhere without reason

When Memoization Backfires

  • Dependency arrays are wrong or too broad
  • Code becomes harder to reason about
  • Cost of memoization exceeds saved work

Part 2

Custom Hooks

Encapsulate reusable stateful logic while keeping components focused on UI.

What Makes a Good Custom Hook

  • Single responsibility and predictable API
  • Clear input/output contract
  • No hidden side effects beyond what name implies

Custom Hook Example

function useDebouncedValue(value, delayMs) {
  const [debounced, setDebounced] = useState(value);
  useEffect(() => {
    const id = setTimeout(() => setDebounced(value), delayMs);
    return () => clearTimeout(id);
  }, [value, delayMs]);
  return debounced;
}

Dependency Pitfalls in Hooks

  • Missing dependencies cause stale data
  • Unstable references trigger unnecessary reruns
  • Move stable utilities outside component when possible

Part 3

Higher-Order Functions + Best Practices

Readable transforms and bounded component responsibilities reduce long-term bugs.

HOFs in React Code

  • map for list rendering
  • filter for scoped subsets
  • reduce for aggregate state
  • Prefer pure transforms over inline mutation

Best Practices Checklist

  • State minimalism over state duplication
  • Effects only for side effects, not pure derivations
  • Memoization only where profiling suggests value
  • Hooks and utility abstractions named by intent

Session Summary

  • Memoization is a tool, not a default rule
  • Custom hooks increase reuse and consistency
  • HOF-driven transforms improve clarity
  • Best practices focus on long-term maintainability
