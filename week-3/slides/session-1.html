Anatomy of a React Application

Before hooks, understand where code belongs and how data flows through the app.

Typical Project Structure

src/
  main.jsx
  App.jsx
  components/
    SearchBar.jsx
    ProductCard.jsx
  hooks/
    useDebouncedValue.js
  services/
    apiClient.js
  pages/
    HomePage.jsx
  styles/
    globals.css

Role of Core Files

  • main.jsx: bootstraps app with createRoot
  • App.jsx: top-level composition and routing shell
  • components/: reusable UI units with props
  • hooks/: reusable stateful logic
  • services/: API and external system wrappers

From Click to UI Update

  1. User clicks button in component
  2. Event handler calls state setter
  3. React schedules re-render
  4. JSX re-evaluates with new state
  5. DOM updates are committed efficiently

JavaScript in JSX

JSX is JavaScript syntax sugar, so expressions and logic are valid in curly braces.

Expressions and Function Calls

const user = { first: "Asha", score: 92 };
const isPassing = user.score >= 50;

<h2>{user.first}</h2>
<p>Final score: {user.score + 8}</p>
<p>Status: {isPassing ? "Pass" : "Retry"}</p>

Conditional Rendering Patterns

Part 4

Environment Variables in Vite

Configure API URLs and other per-environment values without hardcoding them in source.

Why env files?

  • Same codebase, different settings per machine (local vs teammate) or deploy target (staging vs production)
  • Typical files: .env, .env.local (often gitignored), .env.development, .env.production
  • Anything bundled into the client is visible in the browser: do not put real secrets in VITE_* variables

Vite exposure rules

  • Only variables whose names start with VITE_ are exposed to your React code
  • Read them with import.meta.env.VITE_SOME_NAME
  • import.meta.env.MODE — current mode string (e.g. development)
  • import.meta.env.DEV — true in development
  • import.meta.env.PROD — true in production build

Using env in code (axios)

# .env (project root)
VITE_API_URL=https://api.example.com

// app code
import axios from "axios";

const api = axios.create({
  baseURL: import.meta.env.VITE_API_URL,
});

After adding or changing .env files, restart the Vite dev server so values reload.

Part 5

useState: Anatomy and Patterns

State design quality usually determines how maintainable your component becomes.

useState Anatomy

const [count, setCount] = useState(0);
// value: count
// setter: setCount(nextValue)
  • First item is current state value
  • Second item is stable setter function
  • Setter schedules next render, not immediate synchronous mutation

Functional Updates for Safety

const [count, setCount] = useState(0);

function incrementTwiceSafely() {
  setCount(prev => prev + 1);
  setCount(prev => prev + 1);
}

When next state depends on previous state, functional form avoids stale reads.

Array/Object State Update Pattern

const [form, setForm] = useState({ email: "", role: "student" });

function onEmailChange(nextEmail) {
  setForm(prev => ({ ...prev, email: nextEmail }));
}

Never mutate object/array state in place; create new references.

Mini Scenario: Counter + Filter + Form

  • counter: primitive number state
  • filter: primitive string query
  • form: grouped object for related fields
  • Derived values (like filtered length) computed during render

Part 6

useEffect In Depth

Effects synchronize React state with external systems like APIs, timers, subscriptions, and browser APIs.

When useEffect is Appropriate

  • Data fetching after initial render or dependency change
  • Subscribing/unsubscribing to sockets or events
  • Interacting with timers and intervals
  • Syncing with external widgets not controlled by React

Dependency Array Modes

// after every render
useEffect(() => { logRender(); });

// once after mount
useEffect(() => { connect(); }, []);

// mount + when userId changes
useEffect(() => { fetchUser(userId); }, [userId]);

Stale Closure Example

useEffect(() => {
  const id = setInterval(() => {
    console.log(count); // stale when count missing in deps
  }, 1000);
  return () => clearInterval(id);
}, []);

Fix by including count or by redesigning with refs/callback strategies.

Cleanup Pattern for External Resources

useEffect(() => {
  const socket = connectRoom(roomId);
  socket.on("message", handleMessage);
  return () => socket.disconnect();
}, [roomId, handleMessage]);

Cleanup prevents memory leaks and duplicated subscriptions.

Strict Mode Note (Development)

  • Effect setup and cleanup can run twice on mount in development
  • Purpose: reveal unsafe side-effect logic
  • Production behavior is not doubled in the same way

Part 7

useRef and Debouncing

Refs store mutable values across renders without triggering rerenders.

useRef vs useState

useState

  • Triggers rerender on update
  • Use for UI-visible data

useRef

  • No rerender on update
  • Use for DOM handles or mutable instance values

Practical useRef Examples

const inputRef = useRef(null);
const renderCountRef = useRef(0);

useEffect(() => {
  renderCountRef.current += 1;
}, []);

function focusSearch() {
  inputRef.current?.focus();
}

Debouncing Timeline

  1. User types "r" -> timer starts
  2. User types "re" before timeout -> previous timer cleared
  3. User types "react" and pauses -> final timer completes
  4. Only one API call runs for latest input

Debounced Search Example

const [query, setQuery] = useState("");

useEffect(() => {
  if (!query.trim()) return;
  const timerId = setTimeout(() => searchBooks(query), 400);
  return () => clearTimeout(timerId);
}, [query]);

Part 8

State-Only Form Implementation

Build robust forms with controlled inputs and explicit validation state.

Controlled Form Pattern

const [form, setForm] = useState({ name: "", email: "" });
const [errors, setErrors] = useState({});

function onChange(event) {
  const { name, value } = event.target;
  setForm(prev => ({ ...prev, [name]: value }));
}

Submit + Validate + Reset

function onSubmit(event) {
  event.preventDefault();
  const nextErrors = {};
  if (!form.name.trim()) nextErrors.name = "Name required";
  if (!form.email.includes("@")) nextErrors.email = "Valid email required";
  setErrors(nextErrors);
  if (Object.keys(nextErrors).length) return;
  saveUser(form);
  setForm({ name: "", email: "" });
}
